# exp-001-compare · 그냥 Claude Code vs Task A 하네스

2026-11-19 실행. 같은 주장 20건을 모델 3개(Opus·Sonnet·Haiku)와 조건 3개로 한 번씩 판정했습니다. 총 180세션이고 실패는 0건입니다.
실행 방법은 [scripts/run_comparison.py](../../scripts/run_comparison.py), 세션별 판정은 [episodes.jsonl](episodes.jsonl), 전체 지표는 [summary.json](summary.json)에 있습니다.

## 질문

"그냥 Claude Code로 팩트체크하면 되지 않나?"에 답하려고, 같은 Claude Code에 붙이는 것만 바꿨습니다.

| 조건 | 에이전트가 쓸 수 있는 것 |
| :--- | :--- |
| 도구 없음 (`closed_book`) | 아무 도구 없음. 모델이 아는 지식만으로 판정 |
| 그냥 Claude Code (`plain_web`) | Claude Code 기본 웹 검색(WebSearch)과 웹 페이지 열기(WebFetch) |
| 하네스 (`harness`) | MCP 도구만 사용: 원문 코퍼스 C1(54개 문서) 검색·열람, 계산기, `finish_verification`. Skill은 시스템 프롬프트에 붙임. 검증 게이트 적용 |

세 조건 모두 같은 주장 정보(문장, 날짜, 대상 기간, `evidence_cutoff`, 원문 발췌)를 받았습니다. 세션마다 저장소 밖 빈 폴더에서 실행했고, 사용자 설정·플러그인·Skill·다른 MCP 서버는 껐습니다.
각 세션 시작 기록에서 조건별로 의도한 도구만 붙은 것을 확인했습니다.

표본은 반박 11건과 근거 부족 1건 전부에, 지지 8건을 시드 20261119로 뽑았습니다. 이 표본에서 항상 "지지"라고 답하면 정확도는 8/20 = 40%입니다.

## 해석

**판정 정확도에서는 하네스가 그냥 Claude Code보다 낫지 않았습니다.** 세 모델 모두 하네스가 웹을 쓰는 Claude Code와 같거나 낮았습니다. 하네스만 맞힌 주장은 Sonnet에서 2건뿐이었습니다.
도구 없음보다는 Haiku에서만 나았고(13 → 16), Opus와 Sonnet은 같았습니다.

**하네스가 나은 점은 근거가 없을 때 판정을 보류하는 것이었습니다.** 근거 부족이 정답인 FC041은 도구 없음 조건에서 세 모델 모두 "반박"으로 답했습니다.
하네스에서는 Sonnet과 Haiku가 "근거 부족"으로 맞혔습니다. 웹 조건에서는 Haiku만 맞혔습니다. Sonnet의 Macro-F1이 하네스에서만 오른 것은 이 1건 때문입니다. 근거 부족 정답이 1건뿐이라 이 차이는 크게 해석하지 않습니다.

**하네스가 틀린 주장은 대부분 코퍼스나 도구 문제였습니다.** 하네스에서 틀린 답은 모델마다 4건입니다. Sonnet·Haiku는 4건 모두, Opus는 3건이 "근거 부족"이었고, 그때마다 읽은 근거로는 판정할 수 없다고 이유를 적었습니다. Opus의 나머지 1건은 FC041을 "반박"으로 답한 경우입니다.

| 주장 (정답) | 하네스 답 | 원인 |
| :--- | :--- | :--- |
| FC021 (지지) | 세 모델 모두 근거 부족 | 원문 페이지를 수집하지 못해 코퍼스에 문서가 없음 |
| FC039 (지지) | 세 모델 모두 근거 부족 | YouTube 페이지에서 제목과 하단 문구만 추출됨 |
| FC040 (지지) | 세 모델 모두 근거 부족 | `read_evidence`가 문서 앞 4,000자만 보여 줌. 필요한 문구는 9,085자 위치에 있음 |
| FC013 (반박) | Sonnet·Haiku 근거 부족 | 같은 4,000자 제한. 발견 연도는 6,102자 위치. Opus는 `section` 지정으로 찾아서 맞힘 |

즉 이번 하네스는 "읽은 근거로만 판정한다"는 규칙은 지켰지만, 읽을 수 있는 근거가 부족했습니다. 웹을 쓰는 Claude Code는 FC021과 FC013을 세 모델 모두 맞혔고, FC040은 Opus만 맞혔습니다. FC039는 웹 조건에서도 세 모델 모두 틀렸습니다.

**검증 게이트는 잘못된 실행을 막았지만, 비교 대상은 없습니다.** 하네스에서 실행형 미션은 7번 실행됐고, 모두 정답과 같은 판정이었습니다.
Haiku가 FC002를 반박하면서 정정 문장(`correction`)을 빠뜨리자 게이트가 일정 생성을 막았습니다. 비교 조건에는 미션 기능이 없어서, 게이트가 오작동을 얼마나 줄이는지는 이 실험으로 비교할 수 없습니다.

## 다음에 바꿀 것

- `read_evidence`에 이어 읽기(offset) 기능을 넣어 4,000자 뒤의 본문도 읽게 합니다. FC013·FC040이 이 문제입니다.
- 코퍼스에서 빠진 문서(FC021 등)와 본문이 빈 문서(FC039)를 보완합니다. 원문을 구할 수 없으면 해당 주장을 C1 평가에서 따로 표시합니다.
- 고친 뒤 같은 표본으로 하네스만 다시 실행해 이번 결과와 비교합니다.

## 범위와 유의사항

- **표본이 작습니다.** 20건이라 1건이 5%p입니다. 짝 비교에서도 차이가 0~3건이라 어느 조건이 낫다고 통계적으로 말할 수 없습니다. 조건마다 한 번씩만 실행해서 같은 조건 안의 실행 편차도 모릅니다.
- **조건의 정보량이 다릅니다.** 하네스(C1)는 고정 코퍼스 54개만 보고, 그냥 Claude Code는 실시간 웹 전체를 봅니다. 그래서 이 결과는 "고정 코퍼스 하네스 vs 웹을 쓰는 Claude Code" 비교입니다. 하네스에 웹을 붙인 C2는 돌리지 않았습니다.
- **웹 조건은 시점 제한을 지키는지 확인하지 않았습니다.** `evidence_cutoff`(2026-10-30) 이후 자료를 썼는지 검사하지 않았습니다. 하네스 코퍼스도 2026-11-19에 수집해서, 일부 문서에는 cutoff 이후 내용이 들어 있습니다(FC040 README에 2026-11-18 소식).
- **답 노출 검사:** 대화 기록에서 저장소 이름, `gold.jsonl`, `evaluation.md`를 찾았습니다. 웹·도구 없음 조건에서는 나오지 않았습니다. 하네스 조건 20세션에서는 저장소 경로가 나왔는데, 판정을 제출한 뒤 `finish_verification` 응답에 담긴 미션 파일 경로였습니다. 판정에는 영향이 없고, 실행 뒤 서버가 파일 이름만 돌려주도록 고쳤습니다.
- **Skill 효과는 따로 재지 않았습니다.** 하네스는 도구와 Skill을 함께 넣었습니다. 도구만 쓰는 조건(`--no-skill`)은 실행하지 않았습니다. Skill은 시스템 프롬프트에 붙였고, 격리 작업공간처럼 `.claude/skills/`로 읽히게 하지 않았습니다(프롬프트 버전 `skill-v2-sysprompt`).
- **실행 환경:** Claude Code 2.1.328, 모델 `claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5`. 서버 로그의 `code_commit`은 `10ac7ff…+dirty`인데, dirty는 이번 작업 전부터 수정돼 있던 `uv.lock` 때문입니다. 사전 점검(Haiku 3세션, `exp-001-smoke`)은 집계에서 뺐습니다.
- gold는 독립 검수 전 초안입니다. 원본 대화 기록은 `results/raw/exp-001-compare/`(Git 제외)에만 있습니다.
