# RAGuard — 검색했더니 오히려 틀리는 팩트체크

**한 문장으로 읽기:** 이 논문은 자연적으로 작성된 정치 토론 문서가 팩트체크 모델을 오도하는 상황을 데이터셋으로 만들고, 검색 없는 판정·실제 검색·의도한 문서 직접 제공을 분리해 비교합니다. 외부 웹 검색을 하는 CRAG도 비교하므로, 우리 연구의 가장 가까운 선행연구 중 하나입니다.

원문: **Worse than Zero-shot? A Fact-Checking Dataset for Evaluating the Robustness of RAG Against Misleading Retrievals** · Zeng et al. · NeurIPS 2025 Datasets and Benchmarks. 이 해설은 **arXiv v5, 2026-01-17** PDF 27쪽을 기준으로 작성했습니다. [공식 논문](https://arxiv.org/abs/2502.16101v5) · [PDF](https://arxiv.org/pdf/2502.16101v5) · [데이터셋](https://huggingface.co/datasets/UCSC-IRKM/RAGuard)

## 1. 이 논문을 왜 지금 읽나요?

우리는 고정 문서 집합에서 검색한 근거가 틀리거나 부족할 때, 에이전트가 그 문제를 인식하고 추가 검증으로 회복하는지 궁금해했습니다. RAGuard는 그 앞부분, 즉 **관련 문서를 많이 찾는 것이 판정의 질을 보장하는가**를 직접 실험합니다. 여기에 CRAG의 외부 검색까지 넣었기 때문에 ‘우리는 웹 검색을 추가한다’는 설명만으로 차별성을 세우기는 어렵습니다.

논문의 전개는 명확합니다. 먼저 검색 문서를 ‘정답에 도움이 되는가’라는 기능으로 분류합니다. 다음으로 실제 정치 주장과 Reddit 토론을 연결합니다. 그 문서들을 모델에 넣는 방법을 바꿔 검색기와 판정기의 영향을 구분합니다. 마지막으로 사람이 같은 오도 문서를 어떻게 읽는지 비교하여, 단지 풀 수 없는 문제를 만든 것은 아닌지 살펴봅니다.

우리에게 특히 중요한 점은 **misleading이 반드시 사실 하나를 날조한 문서라는 뜻은 아니라는 것**입니다. 사실을 선택적으로 배치하거나 의견을 강하게 표현하거나 다른 시점의 숫자를 제시해도 모델의 판정이 틀릴 수 있습니다. VitaminC식 국소 사실 교체와 함께 보면 오염 조건의 폭을 넓힐 수 있습니다.

## 2. §1–2 — Task와 근거 유형의 정의

입력은 정치적 주장이고, 출력은 **True 또는 False**입니다. 최종 정답은 PolitiFact 판정에 근거합니다. 문서가 가짜인지 분류하는 일과 주장이 참인지 분류하는 일은 구별합니다.

| 논문 용어 | 이 논문에서의 작동 정의 | 우리 설계에서 읽을 점 |
|---|---|---|
| Supporting | 문서를 보고 모델이 gold와 같은 판정을 내림 | ‘주장을 지지’와 다릅니다. 거짓 주장을 올바르게 반박하는 문서도 여기에 들어갑니다. |
| Misleading | 문서를 보고 모델이 gold와 다른 판정을 내림 | 문서 자체의 객관적 거짓 라벨보다 **모델에 대한 기능적 효과**에 가깝습니다. |
| Unrelated | 모델이 해당 문서를 판정과 무관하다고 봄 | 같은 주제의 문서라도 결정적 사실을 제공하지 않을 수 있습니다. |

예를 들어 2010년의 수치를 묻는 주장에 코로나19 초기의 수치를 제시하면, 두 숫자가 각각 사실이어도 잘못된 시간 비교가 됩니다. 또 어떤 인물에 대한 부정적 의견이 그 인물에 관한 특정 사실을 반박하는 증거로 오인될 수 있습니다. 논문 Figure 1과 §4.3은 이런 **의견–사실 혼동과 시점 혼동**을 설명합니다.

이 정의를 가져올 때는 오염 유형을 두 층으로 기록하는 것이 유용합니다. 사람이 확인한 문서 속 오류 유형과, 실제 모델 출력에 미친 효과를 따로 두면 특정 모델이 틀렸다는 이유로 모든 문서를 본질적으로 거짓이라고 부르는 일을 피할 수 있습니다.

## 3. §2.3–3 — 데이터는 어떻게 만들어졌나요?

최종 데이터는 **주장 2,648개**와 **문서 16,331개**입니다. True 1,333개, False 1,315개이며, 문서 라벨은 supporting 2,685개, misleading 1,812개, unrelated 11,834개입니다. 전체 주장 중 supporting 문서가 있는 비율은 36.1%, misleading 문서가 있는 비율은 29.8%입니다. 모든 주장에 완전한 정답 근거가 준비된 데이터셋은 아닙니다. (PDF p. 5, Figure 3a)

구축 절차는 다음과 같습니다.

1. **주장 수집:** 2000–2024년 미국 대통령 후보의 PolitiFact 주장을 수집합니다. 원래의 세분화된 판정을 이진화하며 중간 범주의 처리는 원문 §3.1의 선별 규칙을 따릅니다.
2. **문서 확보:** GPT-4로 검색어 변형을 만든 뒤, Google 검색을 Reddit으로 제한하고 주장별 상위 10개 게시물을 수집합니다. 여기서 검색 엔진은 데이터셋을 구축하는 수단입니다.
3. **문서 주석:** 각 문서만 제공한 조건에서 GPT-4가 주장 판정을 하게 하고, gold와 비교하여 기능적 라벨을 붙입니다. Claude 3.5 Sonnet·Gemini 1.5 Flash로 일부를 재주석하여 모델 간 일치도도 확인합니다.

<!-- FIGURE:raguard6 -->

**전체 맥락에서 이 페이지의 역할:** PDF p. 6의 Figure 4와 §3은 ‘실제 오도 정보’라는 표현이 어떤 수집·선별·라벨링 절차를 가리키는지 보여줍니다. 자연적으로 작성된 문서를 사용하지만, benchmark의 라벨링과 선별은 모델을 매개합니다. 이 둘을 함께 읽어야 데이터의 성격이 정확해집니다.

**우리에게 가져올 것:** 원문 출처, 사람이 확인한 사실 관계, 문서별 기능적 효과를 분리해서 보관하는 방식입니다. **우리에게 바로 적용할 설계상의 질문:** 평가 모델 자신의 실패 여부로 평가 자료를 골라버리면 비교가 유리하거나 불리하게 정해지지 않는지, 사전 선별용 모델과 평가용 모델을 어떻게 분리할지입니다.

## 4. §4.1 — 실제 검색과 문서 직접 제공을 왜 나누나요?

| 조건 | 모델에 들어가는 자료 | 분리해서 보는 현상 |
|---|---|---|
| Zero-Context | 주장만 제공 | 외부 근거가 없을 때의 판정 |
| RAG-1 / RAG-5 | text-embedding-ada-002로 유사한 문서 1개 / 5개 검색 | 검색기의 선택과 판정기의 사용을 합친 결과 |
| Oracle Retrieval (All) | 주장에 연결된 문서를 직접 제공 | 검색 선택을 거치지 않고 관련 문서 묶음에 노출된 효과 |
| Oracle Retrieval (Misleading) | misleading으로 라벨된 연결 문서 제공 | 오도 문서에 강하게 노출된 경우 |

여기서 **Oracle은 모두 참인 정답 문서라는 뜻이 아닙니다.** 해당 주장에 연결된 문서를 알고 공급한다는 뜻입니다. 이 표현을 ‘gold evidence 제공’으로 읽으면 결과를 반대로 이해하게 됩니다.

이 구분은 우리가 고민한 ‘직접 근거 묶음을 줄 것인가, corpus에서 찾게 할 것인가’에 좋은 답을 줍니다. **고정 근거 노출 실험은 문서를 사용하는 능력**, **corpus 검색 실험은 노출되는 근거의 선택까지 포함한 능력**을 봅니다. 동일한 연구 질문 안에서 두 단계로 연결할 수 있습니다.

## 5. §4.2–4.3 — 주요 결과를 어떻게 읽나요?

<!-- FIGURE:raguard7 -->

Table 2에서 GPT-4o의 정확도는 Zero-Context **67.33%**, RAG-1 **64.80%**, RAG-5 **65.90%**, Oracle (All) **53.22%**, Oracle (Misleading) **45.97%**입니다. Claude 3.5는 각각 **74.51%, 70.09%, 68.58%, 52.56%, 35.98%**입니다. 비교 기준이 같은 행·같은 모델인지 확인하며 읽어야 합니다.

이 결과는 ‘검색을 하면 항상 나쁘다’가 아니라 **이 데이터셋과 문서 분포에서는 외부 문서가 사전 판정을 손상시켰다**는 증거입니다. 실제로 GPT-4o의 RAG-5가 RAG-1보다 높으므로 문서 수가 늘 때 모든 모델에서 단조 감소한다고 말할 수도 없습니다.

논문은 **Misleading Retrieval Recall**도 제시합니다. 이는 misleading 문서를 최소 하나 검색한 **주장의 비율**이며 RAG-1에서 21.3%, RAG-5에서 44.8%입니다. 일반적인 ‘관련 문서 중 몇 개를 회수했는가’라는 document recall과 분모가 다릅니다. 우리 문서에서는 혼동을 피하려고 *Misleading Exposure Rate*처럼 뜻이 드러나는 별도 이름을 붙일 수도 있습니다.

## 6. CRAG의 외부 웹 검색도 이미 비교했습니다

<!-- FIGURE:raguard8 -->

PDF p. 8의 **Existing Robustness Method** 문단을 꼭 함께 읽으세요. Llama 2의 검색 없는 정확도는 **50.57%**, 이 데이터의 Oracle Retrieval 조건에서 CRAG는 **37.24%**입니다. CRAG의 관련성 평가가 낮으면 corpus 밖의 웹 검색을 수행하며, 이 메커니즘이 **70.1%의 사례**에서 작동했다고 보고합니다.

논문은 일반적인 웹 자료가 복잡한 정치 주장에 충분히 직접적인 근거를 주지 못하고, 기존 문서와 웹 문서를 합치며 오도 정보 노출이 늘 수 있다고 해석합니다. 이것은 특정 재현 설정에서의 실패 분석입니다. 모든 외부 검색이나 모든 교정 정책이 실패한다는 보편적 결과는 아닙니다.

따라서 우리 발표에서는 **‘기존에는 오도 문서 뒤에 외부 검색을 붙이지 않았다’고 말하지 않습니다.** 대신 어떤 근거 조건에서 검색이 발동하고, 실제로 독립적·결정적 근거를 얻었는지, 얻은 후 오답을 고쳤는지, 기존 정답을 손상시키지는 않았는지를 나눠 측정하는 방향으로 질문을 구체화합니다.

## 7. §5–7 — 사람 비교와 논문의 결론

사람 실험은 64개 사례와 4명의 주석자이며, 전문성이 있는 2명과 정치 배경지식이 적다고 응답한 2명으로 구성됩니다. 일반 주석자는 자료를 받고 개선되고, 전문가 집단은 높은 성능을 비교적 유지하는 양상이 보고됩니다. 이 실험의 역할은 인간 능력의 일반적 우월성을 확정하는 것보다 **같은 문서가 언제나 불가능한 추론만 요구하는 것은 아니라는 진단**에 가깝습니다.

논문의 결론은 검색 품질을 단순한 주제 관련성으로만 평가하면 중요한 실패를 놓친다는 것입니다. 편향된 표현, 의견, 시간 범위 등을 판정 근거와 구분하는 능력이 필요합니다. 이 점에서 ‘문서 검색 성공’과 ‘팩트체크 성공’을 분리하는 우리의 연구 방향에 직접 연결됩니다.

## 8. 우리 Task에 어떻게 반영하나요?

**설계에 반영할 요소:** 검색 없는 기준선, 실제 고정 corpus 검색, 직접 근거 노출의 구분; 문서 수와 오도 노출량의 구분; 기존 정답을 오답으로 바꾸는 손상률; 실제 웹 검색을 포함한 교정 기준선입니다.

**차이를 검증할 질문:** 오염 비율·문서 순서·출처 의존성이 바뀌면 추가 검색 정책의 회복률이 달라지는가? 검색을 했다는 사실보다, 독립적이며 충분한 근거가 확보된 경우에 회복이 집중되는가? 최초 판정이 맞은 사례에서는 추가 검색이 얼마나 손상을 일으키는가?

발표 10장에서 DRNoise와 함께 보여주면 **근거에 접근하는 과정**과 **찾은 근거를 사용하는 과정**을 구별하기 좋습니다. 그다음 CRAG·FIRE·BeliefRAG로 넘어가면 ‘실패 진단에서 행동 정책으로’ 논의가 자연스럽게 이어집니다.
