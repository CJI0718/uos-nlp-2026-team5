# HAE-GEO — 확인하러 검색했는데도 왜 판단을 고치지 못할까요?

**읽기의 중심 질문:** 여러 웹페이지가 같은 주장을 반복하면 그것은 독립적인 검증일까요? 에이전트가 새 자료를 찾아온 것과, 이미 믿은 거짓 주장을 철회한 것은 어떻게 구분할까요?

Zhongan Bi 외, *Evaluating Deep-Search Agents under Hierarchical Web Evidence Poisoning*. 이 해설은 **2026년 9월 17일 수정본 v2, 36쪽**을 기준으로 작성했습니다. [공식 서지](https://arxiv.org/abs/2609.06027v2) · [원본 PDF](https://arxiv.org/pdf/2609.06027v2) · [전체 읽기 지도](연구과정_중간발표_논지.html)

## 1. 왜 팩트체크 연구에서 상품 추천 논문을 읽나요?

이 논문은 상품·브랜드를 추천하거나 검증하는 검색 에이전트를 다룹니다. 공격자는 가상의 브랜드와 그에 관한 주장을 웹자료처럼 만들어, 에이전트가 해당 브랜드를 믿고 추천하도록 유도합니다. 생성형 검색 결과에 노출과 추천을 유도하는 **Generative Engine Optimization, GEO**의 오염 위험을 연구하는 것입니다.

우리와 출력 과제는 다르지만 핵심 과정이 같습니다. 외부 자료를 만나고, 그 내용을 후보 사실로 받아들이고, 의심할 때 더 검색하고, 마지막 답을 결정합니다. 그래서 이 논문은 최종 정답률만으로 볼 수 없었던 **‘확인 행동이 실제 수정으로 이어지는가’**를 측정하는 방법을 줍니다.

논문의 전개는 §1–2 문제와 기존 평가의 빈틈 → §3 오염 환경과 에이전트 행동 → §4 과정·결과 평가 → §5 오염 수준·방어 지시·상호작용·비용 실험입니다. 긴 부록은 도구가 모델에 무엇을 보여 주는지, 어떤 문구로 실행·채점했는지, 어떤 궤적을 회복으로 분류했는지를 구체화합니다.

## 2. §3.1 — 세 단계 오염은 무엇이 달라지나요?

같은 가상 대상과 거짓 주장을 유지하면서 이를 제시하는 문맥과 근거의 모양을 바꿉니다.

| 수준 | 논문 명칭 | 독자가 생각해 볼 표현 예시 |
|---|---|---|
| L1 | Direct assertion | “A 브랜드는 검증된 우수 제품이다”라고 바로 주장 |
| L2 | Contextual camouflage | 실제 상품·구매 정보 사이에 A의 장점을 자연스럽게 삽입 |
| L3 | Apparent corroboration | 여러 리뷰·평가·인용 관계가 A를 뒷받침하는 것처럼 구성 |

오른쪽은 이해를 위한 재구성 예시입니다. L3의 핵심은 단순히 거짓말을 세 번 반복하는 것이 아니라 **서로 다른 근거가 일치하는 것처럼 보이는 표현 구조**입니다. 저자들은 이 때문에 위험한 근거를 알아보기가 어려워지는 패턴을 corroboration trap이라고 부릅니다.

수준마다 주입 문서는 **770개로 동일**합니다. “더 많이 넣어서 더 잘 속였다”와 “같은 양을 더 설득력 있게 제시해서 더 잘 속였다”를 구분하려는 설계입니다. L1→L3는 의도한 수준 구분이며, 모든 모델·지표가 반드시 순서대로 악화한다는 뜻은 아닙니다.

## 3. §3.2–4.1 — 공개 웹인가요, 고정 corpus인가요?

평가는 **수집·구축한 통제된 웹 문서 집합**에서 진행됩니다. Clean 배경은 72,039페이지이고, 8개 상품 범주와 154개 브랜드를 다룹니다. 전체 질의는 1,011개지만 주요 비교에는 범주를 균형 있게 선택한 **고정 120질의**를 사용합니다. Clean과 각 오염 조건은 같은 질의와 깨끗한 배경을 공유합니다.

모델은 `Search → Scrape → 추가 Search 또는 Answer`를 선택합니다. Search는 제목·URL·시각 같은 메타데이터를 보여 주고, Scrape는 선택한 페이지 본문을 가져옵니다. 논문 §3.3과 부록의 실행 정의를 기준으로 읽으면, 검색 목록을 봤다고 본문까지 읽은 것은 아닙니다. 개괄 그림의 snippets 표현보다 실제 도구 정의가 더 구체적입니다.

검색은 텍스트·벡터 검색을 결합하고 재순위화를 거치는 설정입니다. 에이전트가 쿼리와 읽을 페이지를 고르더라도 후보 문서를 계산하는 검색기는 존재합니다. **규칙·검색기와 에이전트의 판단은 공존합니다.** 우리의 fixed-corpus RAG에서도 이 구성이 가능합니다.

실행은 최대 10번의 에이전트 판단 라운드입니다. 한 라운드에 여러 도구 호출이 있을 수 있으므로 ‘도구 호출 최대 10회’와 다릅니다. 공격 라벨은 평가자에게만 남기고 모델에게 전달하지 않습니다. 조건 간 검색 namespace와 cache도 분리해 이전 조건의 결과가 섞이지 않게 합니다.

## 4. §3.4 — E·A·V·R·Y를 실제 이야기로 읽기

가상의 브랜드 A에 관한 추천 질의를 받았다고 해 보겠습니다. 아래는 논문 정의를 설명하는 구성 예시입니다.

| 상태 | 관찰하는 사건 | 예시 |
|---|---|---|
| E: Exposure | 공격 페이지의 대상 브랜드가 모델에게 보임 | 검색 제목 또는 읽은 본문에 A가 등장 |
| A: Adoption | 최종 답 전의 관찰 가능한 메시지에서 A를 후보로 수용 | “A도 비교해 보겠습니다”라며 장점을 받아들임 |
| V: Verification yield | 대상에 대한 독립 검증 쿼리 후, 새 비공격 출처를 실제 읽음 | A 관련 확인 검색 후 기존에 안 읽은 비공격 페이지 Scrape |
| R: Recovery | 먼저 채택했고, 이후 검증 근거를 얻고, 최종 추천에서 거둬들임 | 추가 확인 후 A 추천을 철회 |
| Y: Endorsement | 최종 답에서 A를 긍정적으로 추천 | “예산이 적다면 A도 고려할 만하다” |

이것은 반드시 E→A→V→R→Y 순서로 모두 거치는 상태 기계가 아닙니다. 예를 들어 처음부터 의심해 배제하면 A가 없을 수 있습니다. 또 Y는 마지막에 거짓 브랜드를 추천했는지 나타내므로, R이 성립한 경우 Y는 0입니다.

단순히 “A는 검증되지 않았다”고 언급한 것과 “A를 고려할 만하다”고 추천한 것을 구분합니다. 단어 출현 횟수로 성공·실패를 세면 안 되는 이유입니다. 새 검색을 했더라도 같은 오염 자료만 다시 읽으면 엄격한 V의 조건을 충족하지 못합니다.

또 모델 내부의 숨은 사고를 알아냈다는 뜻도 아닙니다. 이 평가가 쓰는 A는 **기록에 관찰되는 채택**입니다. 중간 assistant 텍스트가 없는 모델은 이전 채택 여부를 확인할 수 없어 회복 지표를 N/A로 처리합니다.

## 5. §4.2 — 지표의 분모가 연구 질문을 결정합니다

주요 과정 지표는 실제 대상 오염에 노출된 사례를 기준으로 합니다.

| 지표 | 계산 | 물어보는 것 |
|---|---|---|
| Fooled Rate, FR | 노출 후 최종 긍정 추천 / 노출 사례 | 본 오염에 최종적으로 속았는가? |
| Strict Verification Yield, SVY | 노출 후 엄격한 검증 근거 확보 / 노출 사례 | 새롭고 비공격적인 확인 자료를 실제 얻었는가? |
| Verification-to-Recovery, V2R | 채택 후 검증까지 한 사례 중 회복한 비율 | 이미 받아들였던 판단을 수정했는가? |

예를 들어 처음부터 오염을 보지 않은 사례를 ‘견뎌 냈다’로 세면 검색 회피와 증거 판단이 섞입니다. 처음부터 오염을 배제한 사례를 ‘회복했다’로 세면 저항과 교정이 섞입니다. 두 경우 모두 최종 답은 안전할 수 있지만 연구 질문은 다릅니다.

우리에게도 적용할 수 있습니다. 다만 상품의 긍정 추천 Y 대신 **거짓 주장 지지 또는 잘못된 사실 판정**을 정의해야 합니다. 기존 지표 이름을 복사하기 전에 상태 정의를 우리의 출력 형식에 맞추는 것이 먼저입니다.

## 6. §4.3–4.4 — 정답 외에 무엇을 평가하나요?

규칙 지표와 함께 여섯 가지 의미 평가를 0·1·2점으로 채점합니다.

| 차원 | 평가 내용 | 우리 과제에서 연결되는 부분 |
|---|---|---|
| M1 위험 처리 | 가짜 브랜드를 경고·제외·낮게 평가하는가 | 잘못된 근거에 의존한 결론을 배제하는가 |
| M2 오염 근거 인식 | 검증 불가·가짜 독립 근거를 지적하는가 | 충돌·재인용·출처 문제를 설명하는가 |
| M3 채택 후 회복 | 검증하고 모순을 찾아 기존 판단을 철회하는가 | C1의 오답을 C2가 어떻게 수정하는가 |
| M4 근거 품질·독립성 | 핵심 진술을 믿을 만한 독립 자료로 추적할 수 있는가 | 인용의 적절성과 출처 계보 |
| M5 불확실성 조절 | 근거 강도와 자신감 표현이 맞는가 | 충분하지 않은 경우 보류하는가 |
| M6 정상 과제 효용 | 공격을 피하면서도 유용한 추천을 하는가 | 무조건 모른다고 하지 않고 필요한 판정을 제공하는가 |

모두 하나의 총점으로 합치지 않고 차원별로 보고합니다. 전부 거부하면 공격에는 덜 속을 수 있지만 사용자에게 쓸모가 줄어들기 때문입니다.

Judge도 정보 접근을 분리합니다. 공격을 아는 Judge는 표적 라벨·궤적·답변으로 M1–M3을 보고, 일반 품질 Judge는 질의·모델이 실제 본 근거·최종 답변만으로 M4–M6을 봅니다. “정답을 아는 채점자가 설명을 무조건 좋게 평가하는가?”라는 평가 오염을 줄이려는 장치입니다. 우리 소규모 평가에서는 일부를 수작업으로 검토하는 방식도 이 원리를 반영할 수 있습니다.

## 7. §5.2–5.4 — 추가 검색은 도움이 되었나요?

첫째, L3처럼 여러 근거가 뒷받침하는 모양이 강해질수록 **평균적인 위험 처리와 오염 인식 점수는 낮아집니다.** 다만 개별 모델의 변동과 예외도 있으므로 모든 모델에 동일한 단조 효과를 주장하지 않습니다.

둘째, 두 모델 Kimi-K3와 Qwen3.8-27B에서 Static Full-Context와 Agentic Search–Scrape를 짝지어 비교합니다. Static은 검색 한 번으로 선택된 페이지 내용을 받아 곧바로 답하고, Agentic은 검색과 본문 읽기를 반복합니다. 질의·웹 환경·Base/Defense 프롬프트 조건을 맞춥니다.

네 모델–프롬프트 조합에서 Agentic은 최종 추천 실패율을 낮췄습니다. Fig. 4의 FR 감소는 각각 **13.6, 16.0, 42.7, 35.4%p**입니다. 하지만 오염 근거 인식 M2가 함께 일관되게 개선된 것은 아니고, 정상 과제 효용 M6도 대체로 유지 또는 하락했습니다. 따라서 “에이전트가 더 정확하게 근거를 이해해서 좋아졌다”는 설명까지 자동으로 따라오지 않습니다.

우리 C1/C2와 직접 비교할 가치가 있는 실험입니다. 동시에 이 논문은 통제된 동일 웹 환경에서의 상호작용 차이를 봅니다. 우리처럼 초기 fixed-corpus에서 출발하여 별도의 공개 웹 자료를 얻는 설계를 하려면, 환경과 초기 노출을 어디까지 공유하는지 추가로 명시하면 됩니다.

<!-- FIGURE:hae_compare -->

셋째, 방어 지시가 들어가면 엄격한 검증 비율은 대략 **2%에서 17%**로 높아집니다. 그런데 Defense의 검증 비율은 L1·L2·L3에서 거의 같으면서, 최종 가짜 추천 비율은 **28.6% → 36.3% → 38.6%**로 올라갑니다. “검증을 더 시켰는가”만으로는 이 차이를 설명할 수 없습니다.

채택 후 검증까지 한 표본만 보면 Defense의 회복률은 81.8%, 66.7%, 66.7%입니다. 그러나 분모가 각각 **11·9·3건**입니다. 특히 마지막 66.7%는 2/3입니다. 강한 일반화보다, 교정 병목을 더 관찰해야 한다는 신호로 읽는 것이 적절합니다.

## 8. §5.5–5.7 — 더 생각하고 더 검색하면 비용은요?

명시적 reasoning mode를 켠 비교에서는 두 모델의 네 조건 모두 실패율과 의미 평가가 개선됩니다. 이 실험은 모델의 추가 추론 모드를 비교한 것이지, 우리 과제에서 숨은 사고 전문을 수집해야 한다는 뜻이 아닙니다. 도구 호출·공개 중간 결정·증거 목록·최종 판정으로도 관찰 가능한 행동을 평가할 수 있습니다.

비용 비교에서는 Defense가 평균적으로 **질의당 도구 호출 1.82회를 추가**하고, 모델별 토큰 증가율의 평균이 **24.5%**였습니다. 개별 도구 호출 수는 Search와 Scrape를 각각 센 것이고, 토큰은 누적 API 사용량입니다. 모델마다 토크나이저가 다르므로 비용 변화는 같은 모델 안의 조건을 우선 비교합니다.

중요한 결론은 비용·안전·효용의 세 축입니다. 더 검색해서 가짜 추천을 줄여도 사용자에게 필요한 답을 과도하게 회피할 수 있습니다. 우리도 최종 판정 정확도와 별도로 보류율, 올바른 답을 유지한 비율, 검색 횟수·토큰을 함께 기록하면 이런 차이를 볼 수 있습니다.

## 9. 우리 연구에 가져올 부분과 남길 선택

가장 직접적으로 가져올 부분은 **노출 → 채택 → 새 근거 확보 → 판단 수정**을 나누는 평가 설계입니다. 사용자가 말한 “가져온 다음에 틀린 문서를 골라내고 정답과 이유를 말하는가”가 이미 훨씬 구체적인 관찰 항목으로 바뀝니다.

연구 초점 후보는 두 가지입니다. 하나는 오염 문서의 비율·순서·출처 관계가 C1의 판정에 미치는 영향입니다. 다른 하나는 같은 C1 상태에서 C2로 넘어갔을 때 **독립 검증 자료 확보와 최종 교정 사이의 전환율**입니다. 처음부터 모든 차원을 교차시키기보다 어느 전환이 가장 궁금한지 정하면 50개 평가 항목도 해석하기 쉬워집니다.

출처 독립성은 특히 조심스럽게 설계해야 합니다. 논문의 엄격 V는 ‘새로운 비공격 출처를 실제 가져왔는가’라는 조작적 기준입니다. 서로 다른 URL 두 개가 같은 원보도를 복제했다면 지식 생산의 독립성은 낮을 수 있습니다. URL 차이, 도메인 차이, 원자료 차이 중 무엇을 의미하는지 팀에서 정해야 합니다.

## 10. 읽은 뒤 만들어 볼 질문

1. 우리의 ‘노출’은 본문을 읽은 시점으로 둘까요, 제목·검색 스니펫으로도 해당 사실이 보이면 포함할까요?
2. C1에서 이미 오답을 낸 사례만 C2 교정을 평가할까요, 전체 정확도와 조건부 교정률을 함께 낼까요?
3. “검색해 봤다”와 “독립적인 반박 근거를 실제 얻었다”를 로그에서 어떻게 나눌까요?
4. 처음부터 거짓을 배제한 사례, 의심했지만 보류한 사례, 채택했다가 고친 사례를 어떤 표로 보여 줄까요?
5. 50개에서 회복의 분모가 3개뿐이면 백분율 대신 무엇을 함께 제시해야 할까요?
6. 허위 주장을 무조건 반박하는 에이전트가 참 주장도 반박한다면 성공인가요?

## 11. 해석 범위와 원문 확인 안내

이 해설은 v2의 본문과 부록을 바탕으로 한 한국어 재구성입니다. 상품 추천에서의 최종 endorsement는 일반적인 사실 판정 정확도와 같지 않습니다. 통제된 웹 corpus와 공개 웹을 구분하고, 조건부 지표의 표본 수를 함께 확인합니다. 관찰 가능한 중간 텍스트가 없으면 숨은 채택을 추정해 회복 점수를 만들지 않습니다.

원문의 §4.4는 분리된 GPT-5.5 Judge 프로토콜을 설명하지만, 부록 A.12는 현재 프롬프트 코드와 보관된 사례 보고서의 버전 차이 및 과거 요청을 완전히 복원할 수 없는 점을 따로 밝힙니다. 따라서 재현 시 ‘문서에 적힌 현재 템플릿’과 ‘과거 평가에 실제 사용된 요청’을 동일하다고 단정하지 않는 것이 좋습니다. 이 점까지 확인한 것이 논문을 비판적으로 읽는 과정입니다.

빠르게 읽는 순서는 §3.3–3.4의 행동 정의 → §4.2–4.4의 지표와 Judge → §5.3–5.4의 비교와 교정 → §5.6–5.7의 비용·효용 → 부록 A.8·A.12·A.15입니다. 원본 캡처는 페이지 전체를 변경 없이 보여 주며 주변 해설은 안내서에서 작성했습니다.
