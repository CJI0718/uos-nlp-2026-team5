# DRNoise — 정답의 재료를 찾고도 왜 거짓 요약을 따를까요?

**읽기의 중심 질문:** 참인 기록은 여러 단계로 연결해야 하고 거짓 문서는 정답처럼 한 문장으로 말해 준다면, 에이전트는 어디까지 확인하고 멈출까요?

Jun Nie 외, *DRNOISE: Benchmarking Deep Research Agents in Misleading Evidence Environments*. 이 해설은 **2026년 10월 11일 수정본 v2, 20쪽**을 기준으로 작성했습니다. [공식 서지](https://arxiv.org/abs/2607.17291v2) · [원본 PDF](https://arxiv.org/pdf/2607.17291v2) · [전체 읽기 지도](연구과정_중간발표_논지.html)

## 1. 이 논문을 왜 지금 읽어야 할까요?

우리가 처음 떠올린 문제는 “고정 문서 집합에 거짓 자료가 섞이면, 에이전트가 알아차리고 더 찾아서 교정하는가?”였습니다. DRNoise는 이 문제의 상당 부분을 이미 정면으로 다룹니다. 검색 가능한 환경에 참인 기록들을 그대로 두고, **그 기록들과 충돌하면서도 답을 바로 알려 주는 듯한 문서 한 개**만 추가합니다. 이어서 모델이 무엇을 검색하고, 언제 끝내고, 어떤 답을 채택하는지 봅니다.

그러나 겹친다는 사실보다 이 논문이 문제를 어떻게 잘게 나눴는지가 중요합니다. ‘참인 자료가 DB에 있음’, ‘참인 자료 일부를 읽음’, ‘거짓 답을 반박할 만큼 읽음’, ‘정답을 확정할 만큼 읽음’, ‘실제로 정답을 선택함’은 서로 다른 상태입니다. 이 구분 덕분에 우리가 고민했던 “retrieval에서 갈리면 연구가 흐려지지 않을까?”를 실험 설계의 질문으로 바꿀 수 있습니다.

**논문의 전체 전개:** §1–2에서 문제와 기존 연구의 위치를 설명하고, §3에서 통제된 데이터셋을 만듭니다. §4는 검증 도중 멈추는 과정을 수학적으로 분해합니다. §5–6은 공통 실행 환경과 성능 저하를 보여 줍니다. §7은 프롬프트·출처 표현·검색기·근거 접근성을 바꾸어 실패가 어디서 생기는지 좁힙니다. 부록은 데이터의 유효성, 증명, 실제 궤적을 뒷받침합니다.

## 2. §3 — 질문 하나와 문서 집합은 어떻게 생겼을까요?

논문 Table 1의 예시는 공급업체 선택 문제입니다.

> 2024년 3월 31일에 안전 인증이 유효했고, 3월 배송 세 건을 모두 제때 완료한 공급업체는 어디인가?

정답은 **Brindle Components**, 주입된 거짓 답은 **Orison Fabrication**입니다. 이는 논문이 만든 평가 세계의 예시입니다. 실제 업체에 대한 주장으로 읽지 않습니다.

| 구성 | 들어 있는 정보 | 에이전트가 해야 할 일 |
|---|---|---|
| 참인 경로 A | 승인 업체 목록, 인증 만료 기록, 배송 예정·도착 기록 | 업체 식별자를 연결하고 인증과 배송 조건을 교집합으로 확인 |
| 참인 경로 B | 별도의 지급·출입 시각 관련 기록들의 조합 | 다른 기록 조합으로 같은 답에 도달 |
| 거짓 요약 F | “두 조건을 모두 충족한 업체는 Orison”이라는 업계 리뷰 | 편리한 결론을 원기록과 대조 |

어느 참인 문서도 “정답 업체는 Brindle입니다”라고 한 번에 말해 주지 않습니다. **간접적인 참과 직접적인 거짓의 비대칭**이 핵심입니다. 문서 다수결을 시키는 실험과도 다릅니다. 참인 기록 여러 개가 하나의 조건 결합을 완성해야 합니다.

Clean은 `배경 문서 + 참인 경로 A + 참인 경로 B`, Noisy는 `Clean + 거짓 요약 F`입니다. 질문·정답·참인 기록은 같습니다. 다만 F를 넣으면 검색 순위와 이후 쿼리가 달라질 수 있습니다. 이것도 오염이 시스템에 미친 영향에 포함됩니다.

## 3. §3.2–3.3 — ‘정답이 분명한 데이터’라는 조건

총 **100문제, 10개 근거 연산 유형별 10문제**입니다. 문제별 문서 1,750개는 간접 기록 1,650개와 거짓 요약 100개로 구성되고, BrowseComp-Plus 배경 문서와 함께 검색됩니다. 필터링, 조건 교집합, 시점 비교, 조인, 순위, 집계처럼 여러 기록을 연결하는 작업을 포함합니다.

저자들은 과제와 문서를 직접 작성하고, 각 문제의 정답이 하나인지, 두 기록 경로가 같은 답을 내는지, 거짓 요약이 같은 대상·시점·조건에서 정답과 충돌하는지 확인했다고 설명합니다. 여기서 ‘같은 조건’이 중요합니다. 2023년 인증과 2024년 인증이 다르다는 이유만으로 문서가 모순이라고 할 수 없기 때문입니다.

선택·순위·집계 문제는 **후보 집합의 완전성**도 요구합니다. 어떤 업체가 목록에 없다는 사실만으로 그 업체가 조건을 충족하지 못한다고 판정하면 안 됩니다. 기록이 해당 후보 영역을 충분히 덮고 있어야 합니다. 우리가 원자화된 주장부터 시작하려는 이유를 이 대목과 연결할 수 있습니다. 원자화는 판정 조건과 근거 충분성을 관리하기 쉽게 만듭니다.

두 경로의 ‘corroboration’은 서로 다른 기록 조합이 같은 답을 지지한다는 뜻입니다. 출처 생성 과정이 통계적으로 독립이라는 뜻은 아닙니다. 우리 연구에서 출처 독립성을 주장하려면 문서 개수와 별도로 원자료·재인용 관계를 정의해야 합니다.

## 4. §4 — 참을 조금 읽는 것, 거짓을 반박하는 것, 정답을 아는 것

가상의 후보가 A·B·C 세 개라고 생각해 보겠습니다. 거짓 요약은 A를 정답이라고 말합니다.

| 지금 읽은 참인 기록으로 가능한 답 | 판정할 수 있는 것 |
|---|---|
| A·B·C | 아직 A를 반박하지 못함 |
| B·C | A는 틀렸다고 반박 가능하지만 정답은 미확정 |
| B | A를 반박하고 정답 B도 확정 가능 |

이것은 논문의 가능한 답 집합 `Aᵢ(Hₜ)`를 풀어 쓴 **설명용 예시**입니다. 논문에서는 가능한 답이 하나가 되는 상태를 identification, 지정 거짓 답이 가능한 집합에서 빠지는 상태를 refutation으로 나눕니다. 정답을 확정하면 거짓 답도 반박되지만, 반박만으로 정답이 정해지지는 않습니다.

그다음 거짓 답 채택 확률을 다음처럼 분해합니다.

`거짓 답 채택 확률 = (반박 근거를 얻지 못할 확률 × 그 경우 거짓을 택할 확률) + (반박 근거를 얻을 확률 × 그래도 거짓을 택할 확률)`

원문 식은 `d = (1 − r)δ₀ + rδ₁`입니다. **검색으로 반박 근거를 확보하는 실패**와 **확보한 반박 근거를 사용하지 않는 실패**가 따로 존재한다는 뜻입니다. 토큰을 더 주어 첫 번째를 개선해도 두 번째가 남을 수 있습니다.

정리 1은 남은 검색 예산, 검색 한 번의 진전 가능성, 중간 종료 가능성 등에 조건을 두어 검증 성공의 경계를 계산합니다. 이를 “예산을 늘리면 모든 에이전트의 오류가 이 비율로 준다”는 실측 법칙으로 읽기보다, **너무 일찍 멈추면 사용하지 않은 예산은 도움이 되지 않는다**는 구조를 이해하는 데 쓰면 좋습니다.

## 5. §5 — 에이전트는 실제로 어떻게 실행되나요?

실행은 공통 ReAct형 하네스에서 이루어집니다. 모델이 쿼리를 만들면 검색기가 문서를 돌려주고, 모델은 이를 읽어 다음 검색 또는 종료를 선택합니다. 최대 100회 반복, 검색당 상위 5문서, 문서당 512토큰 스니펫을 사용합니다. Dense retrieval은 Qwen3-Embedding-8B, 스니펫 제공은 Lucene 인덱스를 사용합니다.

따라서 여기서 ‘검색’은 **구축해 둔 닫힌 문서 환경을 검색하는 것**입니다. 공개 웹 어디든 나가 최신 공식 문서를 가져오는 우리의 C2와는 접근 가능한 자료 범위가 다릅니다. 반면 ‘고정 문서 환경 안에서도 에이전트가 쿼리와 종료를 능동적으로 고를 수 있다’는 점은 매우 직접적인 참고가 됩니다.

모델 다섯 개의 본 실험은 각 조건을 3회 실행한 평균과 표준편차를 제시합니다. 이후 GPT-5.4의 상세 진단은 **고정한 단일 기준 실행**을 사용합니다. 아래 두 종류의 숫자가 다른 이유입니다.

## 6. §5.2–6 — 성능 저하와 거짓 답 추종은 다른 지표입니다

| 모델 | Clean 정확도 | Noisy 정확도 | 감소 폭 | Conditional deference |
|---|---:|---:|---:|---:|
| Gemini 3.5 Flash | 96.3% | 26.0% | 70.3%p | 72.6% |
| MiMo v2.5 | 82.0% | 1.0% | 81.0%p | 96.3% |
| GPT-5.4 | 81.7% | 15.7% | 66.0%p | 80.4% |
| DeepSeek V4 Flash | 88.7% | 1.0% | 87.7%p | 98.1% |
| Qwen3-32B | 13.0% | 5.7% | 7.3%p | 61.3% |

Table 2의 3회 평균을 옮겼습니다. 표준편차는 아래 원본 페이지에서 함께 볼 수 있습니다. Deference는 **Clean에서 맞혔던 문제 중, Noisy에서 주입자가 지정한 거짓 답을 낸 비율**입니다. 다른 오답이나 답변 포기는 여기에 포함되지 않습니다. 각 반복의 분모도 그 반복에서 맞힌 문제 수입니다.

Qwen의 감소 폭이 작다고 가장 강건하다고 판단하면 안 됩니다. Clean부터 13%만 맞혀서 손상될 수 있는 정답 집합 자체가 작습니다. 이는 우리가 C0 또는 C1-clean에서의 기본 성능과 오염 후 변화율을 함께 보고해야 하는 이유입니다.

## 7. §7 — 참인 기록도 전부 한 번은 찾았는데 왜 실패했을까요?

GPT-5.4 단일 진단 실행에서 Clean과 Noisy 모두 **100문제 전부에서 참인 기록을 적어도 하나 검색**했습니다. Noisy에서는 100문제 모두 거짓 요약도 검색했습니다. 하지만 온전한 주석 근거 경로를 확보한 비율은 45%에서 16%로, 평균 검색 횟수는 7.1회에서 4.5회로 줄었습니다.

Clean에서 맞혔다가 지정 거짓 답으로 바뀐 68문제도 모두 참과 거짓에 함께 노출됐습니다. 그중 완전한 경로를 찾은 것은 10문제였습니다. 이 결과는 ‘참 문서가 검색됐음’이라는 느슨한 지표로는 충분한 검증을 설명할 수 없다는 것을 보여 줍니다.

동시에 부록 L의 세 궤적을 자세히 보면 두 종류의 실패가 나옵니다. 하나는 결론을 확정할 정보가 부족한 채 멈춘 경우이고, 다른 두 경우는 이미 명시적인 반박 정보가 나왔는데도 거짓 값을 채택한 경우입니다. 그중 공급업체 사례에는 정답까지 식별 가능한 기록이 있었습니다. **덜 찾은 문제와, 찾고도 잘못 사용한 문제를 둘 다 봐야 합니다.**

이 세 사례는 실패의 존재를 구체화하는 질적 분석입니다. 전체 실패 중 각 유형의 비율을 추정한 숫자로 사용하지 않습니다.

## 8. §7 — 무엇을 바꿨을 때 회복했나요?

| 개입 | GPT-5.4 단일 실행의 Noisy 정확도 | 이 비교가 던지는 질문 |
|---|---:|---|
| 기본 검색 | 12/100 | 출발점 |
| 일반적인 검증 지시 추가 | 28/100 | “한 번 더 확인하라”로 충분한가? |
| 요약과 원기록을 구분하도록 구체적으로 지시 | 67/100 또는 64/100 | 어떤 확인 행동을 요구해야 하는가? |
| 참인 경로 하나를 직접 정답을 말하는 보고서로 변경 | 63/100 | 참과 거짓 사이의 접근 난이도가 영향을 주는가? |
| 참인 원기록 전체를 직접 제공, 거짓 요약 없음 | 100/100 | 검색 병목을 없앤 기준 |
| 참인 원기록 전체와 거짓 요약을 직접 제공 | 91/100 | 자료를 모두 봐도 오도 효과가 남는가? |

구체적 지시 두 개는 공격 구조를 알고 ‘요약 대 원기록’을 강조한 회복 탐침입니다. 일반적인 검증 지시와 같은 정보 조건의 공정한 방어 비교로 해석하지 않습니다. 반대로 전체 근거 제공은 우리가 고민했던 **검색을 시키는 실험과 의도한 근거 묶음을 직접 주는 실험을 함께 두는 이유**를 아주 선명하게 보여 줍니다.

출처 표현도 바꿉니다. 같은 거짓 값을 익명 포럼 문체로 주면 deference가 54.3%, 업계 리뷰로 주면 84.0%, 감사 보고서로 주면 82.7%였습니다. 표면적 신뢰 단서가 영향을 주지만 권위가 높아질수록 반드시 단조롭게 더 속는다고 요약할 수는 없습니다.

BM25를 사용해도 거짓 답 추종은 나타났습니다. 다만 dense의 Clean 정답 81개와 BM25의 23개는 다른 조건부 집합이므로, deference 84% 대 100%만으로 검색기의 강건성을 서열화하면 안 됩니다.

## 9. 우리 연구에 가져오면 무엇이 달라질까요?

**설계에 가져올 것:** 문서가 corpus에 들어 있는 비율과 실제 context에 들어온 비율을 따로 기록합니다. 정답 문서 일부를 찾았는지와 결정적인 반박을 찾았는지도 구분합니다. 동일한 주장에 깨끗한 조건과 오염 조건을 대응시키고, 오염에 따른 정답→지정 오답 변화와 교정을 함께 봅니다.

**비교할 수 있는 것:** DRNoise가 간접 참 기록과 직접 거짓 요약의 비대칭을 강조한다면, 우리는 원자화된 사실 주장에서 문서 비율·순서·출처 관계 중 무엇을 주된 조작으로 택할지 정할 수 있습니다. C1의 초기 노출을 공유한 C2가 독립적인 외부 근거를 얻었을 때 어떻게 판단을 수정하는지도 추적할 수 있습니다.

다만 ‘우리만 검색을 더 한다’는 차별점은 성립하지 않습니다. DRNoise도 검색과 검증 개입을 수행합니다. 우리의 초점은 **어떤 자료 환경과 어떤 교정 단계에서 무엇을 비교하는가**로 좁혀야 합니다. 예를 들어 “잘못된 초기 근거를 채택한 뒤, 독립적인 반박 근거가 실제로 도착했을 때 최종 판정이 수정되는가?”는 단순 최종 정확도보다 뚜렷한 연구 질문입니다.

또 이 데이터의 공급업체 같은 인공 사실은 모델이 원래 알고 있었을 가능성을 관찰하려는 C0 표본과 목적이 다릅니다. 자연 사실 기반 실험과 합성 세계 실험의 역할을 나누어 읽는 편이 좋습니다.

## 10. 읽은 뒤 만들어 볼 질문

1. ‘참인 자료가 있다’는 말을 corpus 존재·부분 노출·반박 가능·정답 식별의 어느 수준으로 쓰고 있나요?
2. 우리 사실 주장에도 두 개의 간접 근거 경로가 필요한가요, 아니면 한 개의 명확한 공식 근거가 적절한가요?
3. 거짓 문서 한 개가 직접 답을 말하기 때문에 생기는 효과와, 문서 수·출처·순서 효과를 어떻게 구분할까요?
4. C2가 잘못된 답을 고쳤다면 더 많이 검색한 효과인가요, 독립적인 자료를 얻은 효과인가요, 이미 본 자료를 다시 해석한 효과인가요?
5. 정답을 맞히지 못해도 거짓 답을 명시적으로 기각한 경우를 별도 결과로 기록할까요?
6. 검증 프롬프트에 ‘가짜 요약이 있다’고 알려 주면 실제 사용 환경과 얼마나 달라질까요?

## 11. 해석 범위와 원문 확인 안내

이 문서는 원문의 논지·설계·결과를 한국어로 재구성한 독서 해설입니다. 수치와 사례는 해당 v2의 보고이며 우리 팀의 실험 결과가 아닙니다. 수학적 경계는 명시한 가정 아래의 결과이고, 사례 감사는 전체 비율 추정이 아닙니다. 공개 웹의 최신 사실 검증, 장기적인 모델 신뢰성, 출처의 실제 독립성에 대한 결론으로 확대하지 않습니다.

PDF는 §3–7을 먼저 읽고, 데이터 구성은 부록 A–B, 평가·조건부 지표는 C–D, 수학은 E–F, 검증 지시와 상세 궤적은 후반 부록으로 이어가면 좋습니다. 위 캡처는 원본 페이지 전체이며 주변 설명은 이 안내서의 해설입니다.
