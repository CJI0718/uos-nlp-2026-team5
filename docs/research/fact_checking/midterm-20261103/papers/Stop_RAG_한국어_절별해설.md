# Stop-RAG — 더 찾을 가치가 있는지를 학습하는 제어기

**한 문장으로 읽기:** 생성 모델을 다시 학습시키는 대신, 지금 멈출 때와 검색을 계속할 때의 답 품질을 예측하는 별도 Q-network를 학습시켜 반복 RAG의 종료 시점을 정합니다.

원문: **Stop-RAG: Value-Based Retrieval Control for Iterative RAG** · Jaewan Park, Solbee Cho, Jay-Yoon Lee · NeurIPS 2025 MTI-LLM Workshop. 이 해설은 **arXiv v1, 2025-10-16**, PDF 16쪽을 기준으로 합니다. [공식 논문](https://arxiv.org/abs/2510.14337v1) · [PDF](https://arxiv.org/pdf/2510.14337v1) · [논문이 연결한 코드](https://github.com/chosolbee/Stop-RAG)

## 1. BeliefRAG를 읽은 다음 왜 이 논문인가요?

BeliefRAG를 읽으며 ‘상태를 명시하고 규칙으로 행동을 정한다면, 그 행동 선택을 학습할 수도 있지 않을까?’라는 질문이 생겼습니다. Stop-RAG는 그 생각과 직접 연결됩니다. 다만 모든 도구를 고르는 범용 정책을 학습하지 않고 **STOP 또는 CONTINUE라는 작은 행동 공간**에 집중합니다.

핵심 구별은 현재 답의 자신감과 추가 검색의 가치입니다. 지금 답이 그럴듯해도 한 번 더 검색하면 빠진 연결고리를 찾을 수 있습니다. 반대로 지금 자료가 혼란스러워도 더 찾는 행동이 오히려 방해 문서를 늘릴 수 있습니다. 저자는 그래서 현재의 품질만 추정하는 것보다 **지금 종료한 결과와 계속 진행한 결과를 함께 예측해야 한다**고 주장합니다.

논문 흐름은 문제 제기 → Q(λ) 배경 → 반복 RAG의 MDP 정의 → 완전 trajectory로 학습 데이터 구성 → 별도 제어기 학습 → 기존 pipeline에 부착 → 답 품질과 검색 횟수 분석 순서입니다.

## 2. §1–3 — 무엇을 학습하고 무엇을 고정하나요?

| 구성 요소 | 맡는 일 | Stop-RAG의 역할 |
|---|---|---|
| Query / answer generator | 검색 질의와 중간·최종 답 생성 | 제어기 학습을 위해 생성 모델 전체를 업데이트하는 구조가 아닙니다. |
| Retriever / reranker | corpus에서 후보 검색 후 순위화 | 기존 pipeline의 도구로 사용합니다. |
| Q-network | 두 행동의 미래 답 품질 예측 | 이 논문이 학습하는 핵심 모듈입니다. |
| Stopping rule | 두 예측값 차이와 임계값 비교 | 검증 집합에서 정한 margin으로 실제 종료를 결정합니다. |

Q-learning의 ‘Q’는 행동 가치(action value)를 뜻합니다. 상태가 주어졌을 때 지금 멈추거나 계속하는 행동이 얼마나 좋은 최종 결과로 연결될지 추정합니다. 논문은 **미리 모은 trajectory로 학습하는 offline 학습 구성**을 사용합니다. Offline은 데이터를 수집하는 시점의 구분이고, off-policy는 학습 대상 정책과 자료를 만든 정책의 관계이므로 같은 단어가 아닙니다.

§3의 full-width forward-view Q(λ)는 여러 단계 미래를 보는 target을 혼합합니다. 행동이 두 개이고 STOP이 바로 끝나므로 행동 수준의 가지를 펼치기 쉽습니다. 그러나 CONTINUE의 도구·모델 출력은 확률적이므로 가능한 모든 미래 세계를 완전히 탐색한다는 뜻은 아닙니다.

## 3. §4.1 — 반복 RAG를 MDP로 쓰면 무엇이 되나요?

<!-- FIGURE:stop4 -->

PDF p. 4의 Figure 1은 핵심 구조를 보여줍니다. 파란 상태에서 STOP을 선택하면 종료 상태로 갑니다. CONTINUE를 선택하면 질의 생성 → 검색·재정렬 → 중간 답 생성의 한 번의 반복을 수행합니다. 최대 반복 횟수에 도달해도 종료합니다.

| MDP 요소 | 논문에서 대응하는 것 |
|---|---|
| State | 원 질문과 지금까지 축적한 상호작용 기록 |
| Action | STOP / CONTINUE |
| Transition | STOP은 즉시 종료, CONTINUE는 RAG 한 단계 수행 |
| Reward | 종료 시점 답의 품질 |
| Horizon | 허용한 최대 검색 반복 수 |

수식 설명에는 정답 A₀가 포함된 학습용 상태 표기가 등장하지만, **실제로 Q-network에 넣는 텍스트는 질문 Q₀와 검색 문서 d₁…dₜ**입니다(§5.3). 정답은 학습 reward 계산에 사용합니다. 중간 질의와 중간 답도 실제 입력 표현에서는 제외합니다. 이 차이를 읽지 않으면 ‘추론 때 정답을 주는가?’라는 오해가 생깁니다.

우리 실험에서도 gold와 모델에게 공개되는 state를 다른 파일·필드로 분리해야 합니다. 관측 상태는 문서·출처·시점·검색 이력이고, 정답은 평가자가 사용하는 정보입니다.

## 4. §4.2 — 학습용 trajectory와 reward는 어떻게 만들까요?

<!-- FIGURE:stop5 -->

처음부터 잘 멈추는 정책으로 자료를 모으지 않습니다. 우선 모든 문제를 최대 길이까지 계속 진행하여 **완전한 trajectory**를 만듭니다. 그다음 첫 1단계, 첫 2단계, …처럼 각 prefix를 하나의 상태로 봅니다.

각 상태에서 ‘여기서 멈추면 무슨 답이 나올까’를 측정하기 위해 독립적인 답 생성 **8회(N=8)**를 수행하고 gold와의 **F1 평균**으로 종료 reward를 추정합니다. 계속 행동의 중간 reward는 0이고, 마지막 단계에서는 최종 답 품질로 보상합니다. 도움이 되는 신호가 없는 일부 상태는 학습에서 걸러냅니다.

STOP target은 해당 시점의 답 품질이고, CONTINUE target은 앞으로 더 진행했을 때 얻을 수 있는 품질을 여러 길이의 return으로 추정합니다. 학습 중 λ를 1에서 작은 값으로 낮추며 긴 미래를 직접 보는 target과 더 짧게 bootstrap하는 target의 비중을 조정합니다.

**계산 비용이 생기는 지점:** 작은 행동 공간이라고 데이터 생성도 자동으로 저렴해지는 것은 아닙니다. 여러 trajectory prefix마다 답을 8번 생성하면 생성 모델 호출이 크게 늘어납니다. 별도 Q-network 학습 GPU 비용과 trajectory·reward 수집 비용을 분리해서 견적해야 합니다.

## 5. §5 — 실험 환경과 실제 제어기 구조

데이터셋은 **MuSiQue, HotpotQA, 2WikiMultihopQA**입니다. 여러 근거를 연결해야 하는 multi-hop QA이므로 ‘언제 충분한 근거를 모았는가’를 관찰하기 좋습니다. 공식 train을 학습에 쓰고, dev에서 검증 1,000개와 테스트 1,000개를 각각 샘플링합니다.

검색 환경은 고정 corpus입니다. HotpotQA는 제공된 Wikipedia corpus를 사용합니다. MuSiQue와 2WikiMultihopQA는 원래 읽기 이해 자료의 context들을 합쳐 검색 corpus를 구성합니다. 이 논문의 주 실험을 실시간 open-web 검증으로 읽으면 안 됩니다.

저자의 자체 pipeline은 **Llama-3.1-8B-Instruct**, **Contriever-MSMARCO**, **bge-reranker-v2-m3**를 사용합니다. 반복마다 10개를 검색하고 reranking 후 1개를 사용하며, 최대 반복은 10회입니다. 별도 비교로 CoRAG에도 제어기를 붙입니다.

Q-network는 **DeBERTa-v3-large + STOP/CONTINUE용 두 prediction head**입니다. 두 head 각각은 은닉층 하나인 feed-forward network입니다. 입력은 `[질문] [SEP] [문서1] ... [문서t]`이며, 출력은 두 행동의 가치입니다. 추론 시 `Q(STOP) − Q(CONTINUE)`가 validation에서 정한 임계값을 넘으면 종료합니다. 생성 모델의 내부 hidden state에 접근하지 않으므로 black-box API와도 결합할 수 있다는 논리입니다.

## 6. §6.1 — 결과는 어느 조건에서 좋아졌나요?

<!-- FIGURE:stop7 -->

Table 1의 자체 pipeline에서 MuSiQue F1은 **44.8 → 47.0**, HotpotQA는 **65.0 → 66.1**, 2WikiMultihopQA는 **73.1 → 75.7**로 개선됩니다. 비교 대상은 각각 고정 반복 baseline입니다. 같은 표에서 LLM에게 종료를 직접 판단하게 한 LLM-Stop도 비교합니다.

그러나 **CoRAG + HotpotQA**에서는 F1이 **67.5 → 67.4**, EM이 **55.0 → 54.7**로 소폭 내려갑니다. 초록의 일반적인 개선 표현만 읽기보다 본문의 예외까지 확인해야 합니다. 저자는 고정 반복에 맞춰 학습된 생성기와 해당 retrieval 환경의 높은 recall 필요성이 영향을 줄 수 있다고 해석합니다.

따라서 우리 연구에 가져올 주장은 ‘학습 제어기는 무조건 낫다’가 아니라 **같은 생성기·검색기에서도 종료 정책이 결과를 바꾸며, 그 효과는 pipeline과 데이터의 성격에 의존한다**입니다.

## 7. §6.2 — 적게 검색하는 것과 잘 멈추는 것은 다릅니다

<!-- FIGURE:stop8 -->

Table 2에서 MuSiQue의 평균 반복 횟수는 고정 baseline **10.0**, LLM-Stop **7.6**, Stop-RAG **8.6**입니다. Stop-RAG가 단순 LLM 종료보다 더 오래 검색하지만 recall과 답 품질을 높이는 방향입니다. 2WikiMultihopQA에서도 LLM-Stop 5.0회, Stop-RAG 5.1회입니다.

즉 ‘더 빨리 종료’가 목적의 전부가 아닙니다. **멈추면 손해인 사례에서는 계속하고, 추가 근거가 도움이 되지 않는 사례에서는 종료하는 것**이 목표입니다. 우리도 검색 횟수만 줄였다고 개선으로 보고하면 중요한 실패를 놓칩니다.

Table 3은 학습 target을 바꿉니다. MuSiQue F1은 binary 분류 **43.7**, Monte Carlo **46.2**, Q(λ) **47.0**, Q(0) **46.3**입니다. 단순 이진 행동 정답보다 미래 품질의 정도를 학습하는 가치 target이 이 설정에서 더 효과적이었다는 결과입니다.

또한 주 보상은 답 F1이며, **검색 1회당 명시적인 비용 패널티를 빼는 형태는 이 주 설정의 보상식이 아닙니다.** 비용·지연을 동기로 삼는 것과, 목적함수에 비용을 넣는 것은 구분해야 합니다. 비용 가중 reward는 우리 팀이 선택할 수 있는 별도 확장입니다.

## 8. 우리 팩트체크 Task에는 어디까지 적용할까요?

| 가져올 개념 | 팩트체크에 맞춘 연결 |
|---|---|
| STOP/CONTINUE | 현재 근거로 판정할지 추가 독립 검증을 할지 선택 |
| 질문 + 축적 근거 state | 주장 + given/fetched 문서 + 출처·시점 정보 |
| 종료 답 품질 reward | 올바른 verdict와 충분한 근거를 함께 만족하는 grounded success |
| 여러 prefix의 결과 비교 | 추가 근거가 실제로 판정을 교정하거나 손상시킨 시점 분석 |
| Fixed / LLM-Stop / Learned 비교 | 고정 검색 절차 / 프롬프트 Agent / 학습 제어기 비교 |

Task 자체는 학습 없이도 정의됩니다. **오염된 근거 아래에서 근거를 동반한 올바른 판정을 내리는 것**이 해결할 일이고, RL은 그 일을 수행하는 행동 정책 후보입니다. 먼저 프롬프트·규칙 제어로 실패 유형을 관찰하면 어떤 상태와 보상을 학습해야 할지도 구체화됩니다.

발표 14장에서 BeliefRAG와 나란히 두면 좋습니다. 전자는 명시적 belief state와 제어 절차를 생각하게 하고, 후자는 종료 행동의 가치를 학습하는 방향을 보여줍니다. 두 논문을 소개한다고 중간 발표에서 RL 구현을 약속할 필요는 없습니다.
