## 1. 무엇을 하자는 연구인가

사용자는 하나의 검증 가능한 주장을 줍니다. 에이전트는 고정 문서 집합에서 관련 근거를 검색하고, 자료가 충분한지·서로 충돌하는지·출처가 독립적인지 검토합니다. 필요하면 원문이나 외부 자료를 추가로 조회해, 최종 판정과 확인 근거를 제시합니다.

**해설용 예시:** “A기관은 2022년에 설립됐다.” 초기 검색 결과 다섯 개 중 네 개는 2022년, 한 개는 2010년이라고 합니다. 단순히 많은 쪽을 믿는 대신, 네 문서가 같은 글을 복제한 것인지, 소수 문서가 원본 연혁인지, 같은 기관·시점을 다루는지 확인하도록 합니다. 독립적으로 검수한 gold는 실험 평가에만 사용합니다.

> **Task draft — English**
> Given an atomic claim and access to a fixed evidence corpus, produce a supported, refuted, or insufficient-evidence verdict with cited justification. When the initial evidence is insufficient or conflicting, decide whether and how to obtain additional evidence under a bounded verification budget.

**출력의 세 층:** 주장 판정, 문제 근거의 구체적 위치, 그 판단을 뒷받침하는 출처입니다. “문서들이 다르다”는 관찰과 “이 문서가 거짓이다”는 판정은 나눕니다. 출처 명성이 낮다는 이유만으로 사실 오류 라벨을 붙이지 않습니다.

## 2. 이전 구상에서 유지하는 것과 중심에 두는 것

| 요소 | 이번 작업 방향 |
|---|---|
| 기존 실제 주장 50개 | 가능한 한 보존하고 검증 가능성·원자료 확보 상태를 점검 |
| C0 | 외부 근거 없이 판정하는 행동적 기준선 |
| C1 | fixed-corpus retrieval + 판정; 근거 구성과 오염을 조작하는 중심 조건 |
| C2 | C1과 같은 초기 근거에서 추가 검증을 허용하는 에이전트 |
| agent의 역할 | 충분성·충돌을 판단하고 조회 대상을 선택하며 종료/보류 결정 |
| 후속 Mission·장기 추적 | 별도 확장 아이디어로 보존 |

헌수 님의 기록된 제안인 “오류 유형에 따라 조사 계획을 바꾸고 여러 출처를 대조하는 능력”을 실험으로 관찰하는 방향입니다. 팀원의 실사용 에이전트 구상과 연결하되, 이번 읽기와 실험 설계의 중심은 **검증 단계의 신뢰성**에 둡니다.

학습 cutoff는 실제 지식 보유를 보장하지 않으므로, C0는 “학습에 포함됐다”의 인증이 아니라 모델의 무근거 응답 상태를 관찰하는 용도입니다. 같은 모델·같은 주장 안에서 근거만 바꾼 짝비교가 핵심입니다.

## 3. 선행연구가 이미 한 것

이번에는 Exa에서 두 검색 축으로 후보 16건을 확인하고, 핵심 문헌의 원문·공식 초록을 추가 대조했습니다. 같은 연구의 arXiv·학회 버전은 하나로 묶었습니다. Liner는 기존 NLP Scholar 스레드에서 두 핵심 논문을 1회 후속 요청으로 조사했습니다.

| 문헌 | 이미 한 일 | 우리 설계에 쓰는 위치 | 확인 범위 |
|---|---|---|---|
| [Flip Risk, Roh & Bae 2026](https://doi.org/10.4218/etrij.2026-0242) | 정답 근거 기준선에서 근거 비율·개수·순서를 변형해 오답 전환 측정, 경량 방어 비교 | 가장 가까운 진단 선행연구. 오염 비율 자체를 신규성으로 주장하지 않기 | 본문·PDF·주요 표 |
| [Corrective RAG, Yan et al. 2024](https://arxiv.org/abs/2401.15884) | 검색 결과 관련성 평가 → 정제/웹 보완/결합 → 생성 | 추가 검증을 발동하는 정책의 설계 기반 및 비교 후보 | v3 PDF·본문·공식 코드 설명 |
| [CONFACT, Ge et al. 2025](https://ijcai.org/proceedings/2025/1073) | 서로 충돌하는 근거와 매체 신뢰 정보를 가진 데이터 및 RAG 비교 | 내용 충돌과 출처 신뢰 연구의 직접 비교 대상 | 공식 논문 페이지·검색된 본문 설명 |
| [RA-RAG, Hwang et al. 2025](https://aclanthology.org/2025.emnlp-main.1738/) | 여러 출처를 교차 확인해 신뢰성을 추정하고 출처별 검색·가중 투표 | 출처 신뢰성 추정과 독립성의 차이를 설명 | 공식 초록·방법 설명 |
| [ReliabilityRAG, Shen et al.](https://arxiv.org/abs/2509.23519) | 문서 모순 관계와 신뢰성 신호를 사용해 오염에 대응 | 일관된 다수·신뢰성 기반 방어와 비교 | 저자 초록·공개 메타데이터 |
| [FIRE, 2025](https://aclanthology.org/2025.findings-naacl.158/) | 최종 답변과 다음 검색 질의를 반복적으로 선택 | 추가 조사·종료·비용의 설계 기반 | 공식 초록·방법 설명 |
| [RAGuard, 2025](https://arxiv.org/abs/2502.16101) | Reddit에서 자연 발생하는 오도 검색을 이용해 fact-checking 강건성 평가 | 합성 오염 실험의 현실성을 보완할 후보 | 저자 초록 |

**각 문헌의 의미를 구분하기:** CONFACT는 출처 배경 정보를 활용하는 근거가 되고, RA-RAG는 신뢰성 추정 자체도 이미 연구됐음을 보여줍니다. ReliabilityRAG는 모순과 신뢰성 기반 방어가 가까운 선행 흐름임을 알려줍니다. FIRE와 CRAG는 추가 검색의 존재 자체가 새로움이 아님을 분명하게 합니다.

RAGuard는 인공적으로 문장을 바꾸는 방식 외에 자연스럽게 존재하는 오도 자료를 활용하는 방향입니다. 지금 바로 데이터셋을 전부 바꾸기보다, 합성 실험을 마친 뒤 소수 현실 사례에 같은 현상이 보이는지 점검하는 보완 자료로 생각할 수 있습니다.

검색에서 발견한 MADAM-RAG/RAMDocs, CoVer 등은 주변 확장 후보입니다. 이번 두 해설과 핵심 비교군을 이해한 뒤에 읽도록 하고, 새 이름을 계속 늘리는 것을 연구 진행의 조건으로 삼지 않습니다.

## 4. 우리 기여를 어디에 둘 수 있는가

**기여 후보:** 통제된 근거 오염 조건에서, 에이전트가 단순히 정답을 맞히는지를 넘어 **문제 인식 → 추가 검증 선택 → 확보한 독립 근거 → 판정 회복 → 비용**을 연결해 평가하는 진단 설계.

| 주장하기 어려운 표현 | 더 정확한 연구 서술 |
|---|---|
| 최초로 오염 비율을 바꾸어 평가한다 | 기존 근거 구성 진단을 재현하고 검색·행동·회복으로 확장한다 |
| 최초로 신뢰할 출처를 활용한다 | 문서 수와 출처 독립성이 조사 행동에 미치는 차이를 비교한다 |
| 최초로 RAG 실패 후 웹 검색한다 | 어떤 단서에서 검색을 발동하고 언제 효과가 있는지 평가한다 |
| agent가 항상 우월하다 | 어떤 오염 조건에서 이익·손상·추가 비용이 발생하는지 밝힌다 |

새로움은 최종적으로 가장 가까운 연구의 실험과 대조해 판단합니다. 학부 프로젝트에서는 **정확한 재현, 명료한 확장 질문, 공정한 비교, 실패를 해석하는 능력**도 기여를 설명하는 중요한 부분입니다.

## 5. 작은 실험부터 구성하는 방법

우선 하나의 주장을 검증할 충분한 깨끗한 근거를 확보하고, 같은 대상·시점을 유지한 사실 변형 문서를 만듭니다. 사실 오류와 문체·길이·출처 외형을 항상 함께 바꾸지 않습니다. 인공 변형은 실험용 사본에만 적용하고 원문은 보존합니다.

**파일럿 제안:** 원 주장 5개, 평가용 근거 묶음 크기 k=5를 고정하고 0/5·1/5·4/5 오도 조건으로 먼저 동작을 확인합니다. 이는 비용을 산정하기 위한 작은 예시이며 실제 실행 승인이나 최종 표본 배정이 아닙니다.

두 단계는 서로 다른 질문에 답합니다.

| 단계 | 입력을 어떻게 만드는가 | 답할 질문 |
|---|---|---|
| 통제된 reader 진단 | 정해진 5개 근거 묶음을 직접 제공 | 같은 문서 구성에서 판정·검증 정책이 어떻게 달라지는가 |
| fixed-corpus end-to-end | 전체 corpus를 조작한 뒤 실제 검색기로 top-k 선택 | 검색기가 어떤 근거를 골라 후속 판단을 바꾸는가 |

첫 단계는 디버깅과 원인 분리를 위한 것입니다. 실제 검색을 생략한 결과를 retrieval 성능으로 보고하지 않습니다. 두 번째에서는 corpus 오염 비율뿐 아니라 **실제로 검색된 관련 근거 중 오도 비율**, 검색 순위, 관련 근거 누락을 기록합니다.

출처 독립성은 추가 축으로 작은 대응쌍을 만듭니다. “독립적으로 작성된 문서 여러 개”와 “한 출처의 재인용·복제 여러 개”를 비교하되, 원문 링크·인용 관계처럼 모델이 볼 수 있는 단서를 함께 준비합니다. 문서 복제 자체를 새로운 사실의 확인으로 세지 않는지를 봅니다.

검색 순서·문체·길이는 통제 변수로 관리하고, 처음부터 모두 연구 가설로 확장하지 않습니다. 소수 의견이 참인 조건과 거짓인 조건을 모두 넣어 단순 다수결로도 성공할 수 있는 평가가 되지 않도록 합니다.

## 6. 비교 조건과 에이전트에게 허용할 행동

| 비교 | 역할 |
|---|---|
| C0: No evidence | 근거 없이 모델이 보이는 판정 |
| C1: Fixed-corpus RAG | 초기 근거만으로 판정 |
| C2-adaptive | 동일한 초기 근거에서 조사 필요성·질의·종료 선택 |
| C2-always | 외부 접근권과 최대 예산은 같되 항상 정해진 보완 조회 수행 |

C2-always는 C2의 통제 조건입니다. 결과가 좋아졌을 때 외부 자료를 더 받았기 때문인지, 조사 정책이 효율적이었기 때문인지 구분하게 해줍니다. 별도 기법을 계속 추가하기 전에 이 비교가 작동하는지 확인하는 편이 좋습니다.

추가로 저비용 CA 경고 프롬프트를 C1에 붙이는 비교를 둘 수 있습니다. 관련성 중심 CRAG형 정책은 구현 가능성과 예산을 본 뒤 비교 후보로 선택합니다. T5 평가기를 재현하지 않으면 원형 CRAG라는 이름으로 결과를 보고하지 않습니다.

**최소 도구:** fixed corpus 검색, 외부 검색, 선택한 페이지 읽기. 행동 기록에는 query, 반환 문서 ID·URL·조회시각, 선택 이유의 짧은 요약, 새로 확인한 사실, 종료 이유를 남깁니다. 내부 사고과정 전체를 확보했다고 주장하지 않고 관찰 가능한 행동과 근거를 분석합니다.

외부 검색의 변동은 질의와 응답을 저장해 통제합니다. 반복 비교에는 수집한 응답의 재생 실험을 함께 고려하고, 라이브 검색과 스냅샷 재생 결과를 구분합니다. 모델이 어떤 질의를 선택할지는 허용하되 접근 가능한 도구와 예산은 비교군 간 동일하게 둡니다.

## 7. Task에 맞는 metric 초안

영문 metric 명칭과 정의를 함께 적습니다. 정답은 오염 이전의 독립 검수 자료로 정하며, 최종 답과 별도로 판정에 충분한 근거를 확보했는지도 봅니다.

| Metric | 정의 또는 계산 대상 | 이 태스크에 필요한 이유 |
|---|---|---|
| Verdict Accuracy / Macro-F1 | 전체 독립 주장 및 조건별 최종 라벨 | 최종 task 성과와 라벨 불균형 |
| Contamination-induced Flip Rate | 깨끗한 근거에서 맞힌 사례 중 오염 조건에서 틀린 비율 | Flip Risk와 이어지는 손상 진단 |
| Paired Correction Rate | 같은 초기 근거에서 C1이 틀린 사례 중 C2가 맞힌 비율 | 추가 검증 조건의 회복 효과 |
| Paired Harm Rate | C1이 맞힌 사례 중 C2가 틀린 비율 | 재검증의 부작용 |
| Evidence Error Identification Precision / Recall | 해당 주장에 관한 사실 오류가 있는 문서·구절의 식별 | 단순 소수 의견 배제를 걸러냄 |
| Citation Support Rate | 판정 이유의 검증 가능한 문장 중 인용 근거가 실제 뒷받침하는 비율 | 설명이 근거와 연결되는지 |
| Verification Cost | 검색·fetch·LLM 호출, 토큰, 지연을 분리 집계 | 정확도 향상을 비용과 함께 해석 |
| Retrieved Evidence Composition | top-k의 유효·오도·무관 근거와 독립 출처 수 | 검색 단계와 판정 단계를 연결 |

C1 결과는 짝비교를 위한 평가 기준으로 사용하며 C2에 정답이나 C1의 채점 결과를 보여주지 않습니다. 위의 paired correction은 조건 간 비교이지, 모델이 과거 답변을 스스로 기억하며 수정했다는 증거는 아닙니다. 실제 실행 중 잠정 판정을 기록한다면 모든 비교군에 같은 기록 형식을 적용하고 별도로 분석합니다.

“검색해야 정답”인 라벨을 모든 충돌 사례에 기계적으로 붙이지 않습니다. 주어진 자료만으로 원문 확인이 가능한 경우도 있습니다. 검색 적절성은 사람이 정의한 필요한 정보와 실행 로그로 분석하고, 최종 정확도·근거 충분성·비용을 우선 제시합니다.

50개 기본 주장에서 변형을 만들더라도 통계 단위는 기본 주장입니다. 비율을 제시할 때 분자·분모를 함께 적고, 분모가 0인 교정률은 0%가 아니라 N/A로 표시합니다.

## 8. 읽는 순서와 토론 질문

1. **Flip Risk 1·4·6·7절:** S/R의 기준, 근거 풀 생성, flip의 분모, 결과표를 이해합니다.
2. **CRAG 4·5·6절:** 무엇이 검색을 발동시키는지, 관련성 평가와 진실성 평가가 왜 다른지 봅니다.
3. **Flip Risk 8절 + CRAG 8절:** 검색 없이 정리하는 방어와, 항상 웹을 더하는 비교군을 읽습니다.
4. **이 문서 5–7절:** 기존 50개에서 어떤 사례를 먼저 준비할지와 작은 파일럿을 논의합니다.
5. **CONFACT → FIRE → RA-RAG/ReliabilityRAG:** 출처·조사 정책·비용 중 주된 비교축에 맞춰 확장합니다.

팀 논의에서는 세 가지를 우선 정하면 됩니다. (1) 검증 단계의 신뢰성을 연구 중심으로 삼을지, (2) 주 실험을 오류 비율로 하고 출처 독립성은 추가 실험으로 둘지, (3) 실제 50개 주장 중 원본과 정답 근거를 확보할 수 있는 것을 무엇으로 삼을지입니다.

## 9. 확인 상태와 이번 산출물의 범위

사용자가 이번 대화에서 이 방향을 작업안으로 선택했습니다. 팀 전체 합의, 최종 모델·예산·데이터 확정과는 구분합니다. 연구 결과가 아니라 원문 해설과 실험 설계 문서이며 실제 실험용 LLM 호출은 수행하지 않았습니다.

Exa 검색은 2회, 요청 결과 수 합계 16건이며 중복·주변 후보가 포함됩니다. 핵심 7편을 문헌 지도에 남겼고 두 편을 상세 해설했습니다. Liner는 기존 [NLP Scholar 스레드](https://scholar.liner.com/ko/threads/01a181f2-bd40-72ca-a0af-33e6b4ea3998)에서 1회 요청, 1,938→1,838로 100크레딧 사용했습니다. Liner 연결 API 시도는 결제 요구로 검색이 실행되지 않았고, 별도 결제는 하지 않았습니다.

Liner는 Flip Risk의 초록·서지까지만 확인했지만 ETRI 저장소 경로를 제공했습니다. 이 경로에서 원본 PDF를 추가 확보하고 출판사 본문과 대조했습니다. CRAG는 로컬 v3 원본과 공식 저장소 설명을 확인했습니다. Liner가 확인하지 못한 세부를 확인한 것처럼 옮기지 않고, 직접 확인한 자료로 보완했습니다.

원문 캡처는 변경하지 않은 전체 PDF 페이지를 사용하며 확대해서 볼 수 있습니다. 해설·계산 예시·우리 설계는 원문과 별도입니다. Flip Risk의 KOGL Type 4와 각 원자료의 권리를 보존합니다. GitHub 공개 업로드·커밋·머지는 이번 작업에 포함하지 않았습니다.
