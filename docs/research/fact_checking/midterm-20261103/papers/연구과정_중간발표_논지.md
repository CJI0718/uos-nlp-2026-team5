## 1. 지금의 생각은 타당한가요? — 그렇지만 발표의 연결고리가 중요합니다

**‘선행연구와 겹친 것을 실패로 보지 않고, 질문이 정교해진 과정으로 제시하자’는 생각에 동의합니다.** 연구는 논문을 읽기 전에 떠올린 아이디어를 끝까지 지키는 작업만은 아닙니다. 이미 검증된 부분을 알아보고, 막연했던 단어를 관찰 가능한 사건으로 바꾸며, 자신의 설명에서 잘못된 가정을 고치는 과정도 핵심입니다.

이번 대화에는 실제로 그런 변화가 있었습니다. 처음의 ‘참·거짓을 잘 판별하는 에이전트’에서 출발해, 정답의 기준·파라미터 지식의 관찰·고정 corpus·오염된 자료·능동 검색·출처 독립성·교정의 분모까지 내려왔습니다. 같은 주제를 반복한 것이 아니라 **연구 대상의 해상도가 높아진 것**입니다.

다만 발표를 “이 논문도 있었고, 저 논문도 있어서 다른 주제를 찾았습니다”로 구성하면 문헌 목록처럼 보일 수 있습니다. 더 강한 구성은 다음과 같습니다.

> 처음에는 A라고 생각했습니다. 그러나 논문 X가 B를 보여 주었습니다. 그래서 가정 A를 수정했고, 현재는 조건 C에서 행동 D를 측정하는 Task를 제안합니다.

논문 수보다 **논문이 어떤 설계 결정을 바꾸었는지**를 보여 주는 방식입니다. 이미 있는 연구와 비교한다는 사실이 창의성을 없애지는 않지만, 그 비교를 통해 어떤 구체적인 질문을 선택했는지는 드러나야 합니다.

## 2. 실제 강의 요구사항과 어떻게 맞나요?

이번 확인은 1주차 강의 자료 `main.pdf` 2–3쪽에 근거합니다. 문헌 탐색의 의미와 제출 요건을 분리해서 보면 방향이 명확해집니다.

| 강의 자료의 요구 | 현재 탐색에서 연결할 것 |
|---|---|
| AI Agents로 풀 수 있는 Task 설정 | 충돌하거나 불충분한 자료에서 추가 근거를 구하고 사실 판정을 하는 과제 |
| 평가데이터 50개 작성 | 서로 다른 주장 항목과 정답·근거의 기준을 정리한 평가 묶음 |
| Task 설명 1슬라이드 + 관련 논문 15슬라이드 | 논문마다 한 장보다 연구 질문·설계 결정별로 묶는 발표 |
| 중간: 논문 발표 4점 | 핵심 주장·방법·결과를 정확하게 비교하고 읽은 의미를 연결 |
| 중간: Task 설정 3점 — 창의성 및 난이도 | 관찰하고 싶은 실패와 에이전트 판단이 필요한 이유를 구체화 |
| 중간: 평가 척도 설정 3점 | Task의 성공·실패를 어떤 분모와 지표로 판정할지 제시 |
| 기말: 결과 분석·개선 행동 평가 | 중간의 질문을 실제 실험과 개선으로 이어가기 |

따라서 **지금 모든 실험을 완료할 필요는 없지만, 문헌을 읽은 과정만으로 Task·평가안·50개 데이터 요구를 대신하지는 않습니다.** ‘50개 작성’은 중간 안내에도 나타납니다. 여러 조건에서 같은 주장 10개를 다섯 번 실행했다고 독립 평가 항목 50개가 되는 것은 아니므로, 항목 수와 조건별 실행 수를 별도로 적는 것이 안전합니다.

강의의 ‘잘 풀었나가 아니라 배움을 추구했나’라는 문구는 수시과제 설명에 있습니다. 중간 평가에도 그대로 적용된다고 단정하는 대신, 실제 중간 배점에 맞춰 **배운 내용을 Task와 Metric의 근거로 제시**하면 됩니다. 관련 논문 15슬라이드가 반드시 서로 다른 논문 15편을 뜻하는 것은 아닙니다.

## 3. 우리의 탐색 과정을 ‘질문이 바뀐 이유’로 정리하면

| 처음의 직관·질문 | 읽으면서 생긴 수정 | 현재 설계에 남는 결정 |
|---|---|---|
| 자료를 주면 사실에 더 가까워질 것이다 | 오도·충돌 자료는 정답을 손상시킬 수 있음 | C0·깨끗한 C1·오염 C1의 관계를 볼 필요 |
| 모델이 학습 때 알았는지는 cutoff로 나눌 수 있다 | 공개된 학습 시점은 개별 사실의 기억을 보장하지 않음 | closed-book 응답을 행동 기준으로 관찰 |
| 여러 문서가 같은 말을 하면 충분한 근거다 | 재인용·가짜 corroboration·직접 요약이 판단을 유도할 수 있음 | 문서 수와 근거의 독립성·충분성을 구분 |
| RAG와 ReAct 중 하나를 택해야 한다 | 고정 corpus에서도 모델이 쿼리·읽기·종료를 선택할 수 있음 | 검색기와 에이전트 행동의 역할을 분리 |
| 거짓 자료를 알면 추가 검색으로 해결될 것이다 | 검증을 시도한 것, 반박 근거를 얻은 것, 판정을 고친 것은 다름 | C2의 과정과 최종 결과를 나누어 기록 |
| 더 많은 호출이 더 좋은 검증이다 | 비용이 늘어도 정답·효용이 함께 좋아지지 않을 수 있음 | 성능·정답 보존·교정·비용을 함께 비교 |

이 표를 단순 개인 감상으로 제시하기보다, 각 행의 오른쪽에 관련 결과표·그림 한 개를 붙이면 문헌 발표가 됩니다. 예컨대 DRNoise Table 4는 부분 노출과 충분한 근거를, HAE-GEO Fig. 5는 검증과 교정을, BeliefRAG Fig. 6은 무관한 노이즈와 거짓 근거를 나눌 이유를 보여 줍니다.

## 4. 논문은 연대보다 ‘우리 설계에서 하는 일’로 분류하면 좋겠습니다

사용자가 나눈 두 역할은 유용합니다. **A: 연구를 성립시키는 설계의 토대**, **B: 직접 검증·비교할 질문을 만드는 연구**입니다. 여기에 결과를 어떻게 읽는지 돕는 **C: 평가와 해석의 도구**를 보조 표지로 붙일 수 있습니다. 한 논문이 여러 역할을 맡아도 됩니다.

| 논문·연구군 | 주된 역할 | 발표에서 대답하게 할 질문 |
|---|---|---|
| RAG, ReAct | A | 자료 획득·생성·행동 선택을 어떻게 연결하는가? |
| FEVER | A·C | 주장·라벨·근거를 묶은 팩트 검증 문제는 무엇인가? |
| Claim decomposition 계열, ClaimDecomp, Decomposition Dilemmas | A·C | 복합 주장을 어디까지 나누며 평가 단위는 무엇인가? |
| Dated Data, Real-Document 계열 | A·B | 사전 지식과 외부 문서의 영향을 어떤 통제로 구분하는가? |
| VitaminC | A·B | 다른 조건을 유지하면서 결정적 사실을 바꾸는 대조쌍은 무엇인가? |
| FaithEval, CLASH 계열 | A·B | 문맥 충실성·모순 처리와 실제 참 판정은 어떻게 다른가? |
| ALCE | C | 인용이 붙었는지와 인용이 주장을 지지하는지를 어떻게 평가하는가? |
| Self-RAG, FIRE | A·B | 언제 검색·검증·종료하는가? 판단의 비용은 무엇인가? |
| ClaimCLAIRE | A·B·C | 항목 분해·근거 수집·개별 판정·전체 결과를 어떻게 연결하는가? |
| Astute RAG | A·B | 내부 생성 자료와 외부 자료의 충돌을 어떻게 통합하는가? |
| Flip Risk | B·C | 근거 수·비율·순서가 기존 정답을 얼마나 뒤집는가? |
| CRAG, RAGuard | A·B | 검색 오류·오염을 감지해 다른 근거로 보완하는 비교는 어디까지 이루어졌는가? |
| DRNoise | A·B·C | 근거를 못 찾은 것과 찾고도 사용하지 않은 것을 어떻게 나누는가? |
| HAE-GEO | B·C | 새 검증 근거를 얻은 것이 실제 회복으로 이어지는가? |
| BeliefRAG | A·B·C | 근거 상태를 어떤 행동 규칙과 비용 판단으로 바꾸는가? |

이 표의 Claim decomposition·Real-Document·CLASH는 기존 문헌 풀에서 쓰던 연구군·약칭 표지입니다. 최종 참고문헌에서는 기존 서지의 정확한 제목과 버전을 붙여 사용합니다. [앞선 전체 연구 가이드](../../knowledge-revision/팀공유_연구가이드.html)와 [직전 중복 점검](선행연구_중복점검_2026-11-03.md)을 함께 볼 수 있습니다.

‘기초 → 최신’이라는 순서와 ‘우리에게 기반 → 직접 경쟁’이라는 역할은 다릅니다. FEVER는 2018년, RAG는 2020년이며 CRAG와 Astute RAG는 2024년 연구입니다. FaithEval도 RAG·FEVER와 같은 의미의 오래된 고전으로 묶기보다는 **이번 실험에 필요한 맥락 평가 설계**로 소개하는 편이 정확합니다. ‘CLAIR’는 이번 풀의 **ClaimCLAIRE**를 가리키는지 제목을 통일하면 좋습니다.

## 5. 창의성은 어디에, 난이도는 어디에 둘 수 있나요?

**창의성의 후보는 ‘C0·C1·C2를 처음 비교한다’가 아니라, 근거의 어떤 변화를 조작하고 어떤 전환을 설명할 것인가에 있습니다.** 예를 들어 같은 원자 주장에 문서 비율과 출처 관계를 통제하고, C1에서 생긴 오류가 C2의 새 근거 확보 뒤에도 유지되는지를 짝지어 볼 수 있습니다. 앞선 논문이 다룬 질문을 더 작은 조건에서 재현·확장하는 것 역시 설명 가능한 프로젝트 방향입니다.

다만 ‘한국어로 바꾸었다’나 ‘모델만 바꾸었다’만으로 충분한 기여를 주장하기는 약합니다. 한국어 재인용 기사·공식 기관 자료처럼 **그 환경에서 특별히 어려운 점과 측정할 이유**가 연결되어야 설득력이 생깁니다. 차별성의 크기는 실제 선택한 설계와 결과를 보고 평가할 부분입니다.

난이도는 장황한 방어 코드나 도구 개수보다 다음에 있습니다. 자료는 관련 있어도 틀릴 수 있고, 여러 문서의 일치가 독립 검증을 뜻하지 않으며, 외부 검색을 해도 반박 근거를 못 얻을 수 있습니다. 이 상황에서 에이전트가 **무엇이 부족한지 판단하고, 어디를 더 찾을지 고르고, 얻은 근거로 판정을 수정하며, 비용 안에서 종료**해야 합니다.

이를 관찰 가능하게 만드는 데이터·로그·평가 설계 자체도 기술적인 과제입니다. 학부 프로젝트라면 핵심 조작 한두 개를 선택해 실패 사례까지 설명하는 것이 거대한 완성형 시스템보다 연구 질문에 더 잘 맞을 수 있습니다.

## 6. 지금 제시할 수 있는 잠정 Task와 평가 방향

아래는 팀 논의용 초안입니다. 실제 실행 결과와 구분해 읽습니다.

> **Task — Evidence-Conflict Fact Verification with Adaptive External Checking**
>
> Given an atomic factual claim and an initial fixed-corpus retrieval, determine the claim label, cite decisive evidence, and decide whether additional external checking is needed under a fixed budget. Evaluate how controlled evidence contamination affects judgment and whether newly acquired evidence leads to correction.

쉽게 말하면 **초기 문서가 불완전하거나 서로 충돌할 때, 필요한 외부 자료를 더 구해서 주장에 대한 판정과 근거를 제시하는 과제**입니다. 이 문장은 우리의 의도를 묶은 잠정 정의이며, 정답 라벨 체계와 오염 조작은 팀에서 선택합니다.

| 조건 | 사용 가능한 정보·행동 | 비교의 목적 |
|---|---|---|
| C0 | 주장만, 외부 도구 없음 | 관찰된 closed-book 기준 성능 |
| C1 | 고정 corpus에서 얻은 초기 근거 | 초기 근거의 도움·손상과 오염 효과 |
| C2 | C1과 같은 초기 근거 + 예산 내 외부 확인 | 새 근거 확보와 실제 교정의 효과·비용 |

**초기 근거를 공유한다는 말이 중요합니다.** C1과 C2가 처음부터 서로 다른 검색 결과를 받으면 이후 차이가 능동 검증 때문인지 초기 노출 때문인지 해석하기 어렵습니다. 검색 자체의 실패를 연구하고 싶다면 별도 층위로 기록합니다. 문서 직접 제공 조건을 작은 진단 실험으로 두면 검색 병목과 근거 사용 실패를 나누는 데 도움이 됩니다.

주 지표 후보는 Label accuracy 또는 macro F1, 깨끗한 조건에서 맞혔다가 오염 조건에서 틀린 비율, C1 오답 중 C2가 고친 비율입니다. 보조 지표는 C1 정답을 C2가 유지한 비율, 결정적 반박 근거 확보, 출처 계보 확인, 증거를 반영한 설명, 보류율, 도구 호출·토큰입니다. 지표마다 **누가 분모에 들어가는지와 0건일 때 N/A 처리**를 적습니다.

현재 중간 발표의 목표는 이 후보를 모두 채택하는 것이 아니라, Task의 핵심 성공을 측정할 주 지표와 실패를 설명할 보조 지표를 구분하는 것입니다. 주장 50개를 준비할 때도 참·거짓·시점·기본 난이도 분포와 근거의 판정 가능성을 함께 관리합니다. 최신 사실을 cutoff만으로 ‘절대로 모르는 사실’로 분류하기보다, 공개 학습 정보와 C0 관찰을 서로 다른 열에 두면 좋습니다.

## 8. 이번 세 논문을 읽는 순서와 서로의 연결
