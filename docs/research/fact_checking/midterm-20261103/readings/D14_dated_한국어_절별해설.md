# Dated Data · 한국어 절별 해설

Dated Data: Tracing Knowledge Cutoffs in Large Language Models

**D14 · 2024 · COLM · 5장**

[전체 읽기 목록](README.md) · [해설 기준 판본 PDF](https://arxiv.org/pdf/2403.12958v2) · [공식 서지·원문](https://arxiv.org/html/2403.12958v2)

## 먼저 붙잡을 질문

모델이 최신 상태를 틀렸다면 그 사실이 학습 자료에 한 번도 없었다고 결론 내릴 수 있을까요?

**왜 선택했나 — ‘학습 cutoff 이전/이후’라는 데이터 층화의 가정을 점검한다.** 모델에 붙은 단일 cutoff 날짜가 데이터 자원마다 같은 의미인지 묻는다. 특정 사실을 맞혔다고 학습 표본에 있었다고 결론 내리는 방법을 제안한 논문은 아니다.

## 논문의 논증을 먼저 따라가기

‘어느 날짜까지 학습했다’는 설명은 모델 단위지만, 뉴스나 Wikipedia는 자료마다 서로 다른 시점의 복사본으로 남는다. 연구진은 여러 시점에 걸친 뉴스와 Wikipedia 자료를 준비하고, 모델이 각 버전의 텍스트에 얼마나 높은 가능도를 부여하는지 측정한다. 시간에 따른 perplexity 곡선의 최솟값을 이용해 자료원별로 관찰되는 effective cutoff를 추정한다. Figure 1은 이 측정이 왜 필요한지를 보여주는 도입 예시다.

먼저 여러 모델에서 공표일과 이 추정치가 맞는지 비교한다. 다음에는 훈련 코퍼스가 공개된 경우 실제 자료를 조사해 두 값이 어긋날 경로를 찾는다. 최근 날짜의 CommonCrawl 덤프에도 오래된 내용이 들어가고, 중복 제거가 시점이 다른 유사 버전 중 무엇을 남기는지에 영향을 준다. 따라서 파일이 수집된 날, 문서의 내용이 가리키는 날, 모델에서 상대적으로 친숙하게 보이는 시점은 달라질 수 있다.

우리 사례의 ‘2022년 사건’도 같은 구분이 필요하다. 사건은 2022년에 벌어졌지만 핵심 수치가 정정·확정된 것은 이후일 수 있다. 사건일과 최초 확정일을 주석하고 모델의 자료 없는 응답도 따로 측정하면, 모델이 실제로 보인 답을 기준으로 초기 정답/오답을 층화할 수 있다. 이 측정은 논문이 자료원 단위로 계산한 버전별 perplexity와 구분해 보고한다.

## §3 · 시간이 바뀌며 내용이 갱신되는 텍스트

[PDF pp. 3–5](https://arxiv.org/pdf/2403.12958v2#page=3)

NewsSpan과 WikiSpan으로 뉴스·위키의 여러 시점 버전을 다룹니다. 모델이 어느 버전을 더 자연스럽게 보는지를 점수화하는 probing과, 접근 가능한 사전학습 코퍼스에서 실제 버전을 찾는 mining을 구분합니다. 전자는 행동 측정이고 후자는 자료를 직접 조사하는 절차입니다.

## §§4–5 · 모델 비교와 자료 검색이 답하는 질문

[PDF pp. 5–8](https://arxiv.org/pdf/2403.12958v2#page=5)

공개 모델·코퍼스에서 시간별 문장 버전의 선호와 실제 자료 존재를 대조합니다. 특정 버전에 낮은 perplexity를 주는 것은 모델이 그 문장을 잘 예측한다는 관찰입니다. 특정 사실의 학습 여부를 개인별로 증명하는 표시는 아닙니다. 뉴스와 위키는 갱신·복제 방식도 다릅니다.

## §6 · 중복 제거와 크롤 날짜에서 생기는 어긋남

[PDF pp. 8–10](https://arxiv.org/pdf/2403.12958v2#page=8)

비슷한 문서 여러 개 중 어떤 버전이 남았는지, 새 덤프에도 오래된 내용이 들어 있는지를 조사합니다. 이 단계는 명시된 종료일 앞뒤에 자료가 칼로 자른 듯 나뉘지 않는 이유를 데이터 처리 과정에서 설명합니다.

## §7 · 우리의 ‘이미 아는 사실’은 어떻게 고를까요?

[PDF p. 10](https://arxiv.org/pdf/2403.12958v2#page=10)

대상 날짜와 출처 공개일을 기록하고, 자료 없는 응답을 반복해 안정적으로 맞히는 사례를 찾을 수 있습니다. 이는 실험 전 행동 기준입니다. 해당 사실을 학습 자료에 실제 포함한 것으로 단정하지 않으면, 이후 가짜 문서가 답을 바꿨다는 관찰도 더 정확해집니다.

## 논문 결과와 우리 설계의 경계

**원문에서 보고한 결과.** 보고된 cutoff와 실제 관찰되는 자원별 cutoff가 다를 수 있다. 새 crawl 안의 오래된 자료와 중복 제거 과정이 관련된다.

**우리 연구로 가져올 부분.** 문서 게시일·사건일·최초 확정일·모델 공개일을 구분한다. 우리 세 paraphrase probe는 이 논문의 perplexity 기반 cutoff 추정과 같은 방법이 아니다. 참고한 것은 ‘명목상 cutoff만으로 사실의 학습 여부를 단정하지 말라’는 데이터 설계의 이유다. FreshLLMs의 시간 변화 질문과 함께 읽으면 실제 사례 구성으로 이어진다.

**팀에서 풀어 볼 질문.** 사건은 2020년에 벌어지고 확정 수치는 2022년에 공개됐다면 평가 기준일을 어느 필드에 기록할까요?

### 지식 cutoff가 알려졌는데 왜 closed-book 점검이 필요한가요?

**30초 답변:** “마감일은 특정 사실의 학습·정확한 회상을 보증하지 않기 때문입니다. **학습 자료의 시점, 포함 여부, 응답에서의 접근 가능성**을 구분해야 합니다.”

**풀어서 설명:** Dated Data는 모델이 사용하는 데이터 자원의 버전과 시점이 한 가지 cutoff 표기로 충분히 설명되지 않는 문제를 다룹니다. 날짜 전에 발생한 사실도 빠졌거나 드물게 등장했거나 틀리게 응답할 수 있습니다. 반대로 정답 응답 한 번만으로 실제 학습 데이터 포함을 입증할 수 없습니다.

**연구 연결:** Stable fact 후보는 여러 표현의 closed-book 응답으로 **관찰된 안정성**을 점검합니다. 최신 사실은 문서의 발표일뿐 아니라 **그 정보가 실제로 처음 공개된 시점**도 검토합니다.
