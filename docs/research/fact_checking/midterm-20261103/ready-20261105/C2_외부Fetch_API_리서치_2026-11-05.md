# C2 외부 Fetch 도구 후보와 실험 설계

확인일: **2026-11-05**. Task A의 외부 검증 도구를 선택하기 위한 공식 문서 조사입니다. 실제 유료 API 호출·등록·결제는 수행하지 않았습니다.

## 도구별 역할

| 후보 | 공식 문서에서 확인한 기능 | 우리 C2에서 맡길 역할 |
|---|---|---|
| X API v2 | recent search는 최근 7일, full archive는 2006년부터의 과거 게시물; 키워드·작성자 등 질의 조건 | 원 주장, 당사자 발언, 시점·출처 추적 |
| Exa Search / Contents | 검색 결과 URL·날짜·본문·하이라이트 등 콘텐츠 반환 | 관련 웹 문서 검색과 근거 원문 수집 |
| Tavily Search | 기간·도메인 조건, raw content 및 자동 답변 포함 여부 설정 | 뉴스·웹 근거 탐색; 자동 답변 대신 원문 근거를 observation으로 사용 |
| Brave Web Search | 웹 검색, 기간·언어·국가 조건, 추가 snippets | 검색 목록 탐색과 해당 원문 조회 연결 |
| 공식 기관 API | 예: World Bank Indicators API의 지표 조회 | 해당 주장과 관련된 구조화 수치·기준 연도 확인 |
| 기관·언론 RSS | 특정 공급자의 업데이트 feed를 받아 활용하는 설계 후보 | 새 자료 발견 후 원문 확인; 임의 질의 검색 API와 구별 |

위 API 간 성능 우열을 검증한 것은 아닙니다. 팀의 50개 자료 중 대표 주장으로 **커버리지·한국어 검색·원문 접근·비용**을 점검한 뒤 웹 검색 공급자는 우선 하나를 고정하는 안이 적절합니다. RSS의 구체적 공급자는 주장 주제에 맞춰 선정합니다.

## X API와 xAI X Search는 다릅니다

**X API**는 게시물을 직접 요청해 우리 실험 모델의 도구 입력으로 넣을 수 있습니다. **xAI의 X Search**는 Grok에 제공되는 서버 측 검색 도구입니다. 키워드·의미·사용자·thread 검색을 지원하지만, 모델과 검색 동작을 고정해 비교하려는 실험에서는 Grok 내부 도구와 우리 모델의 검색 래퍼를 같은 것으로 취급하면 안 됩니다. 다른 LLM을 비교할 때는 동일한 X API 결과를 전달하는 방식이 비교 조건을 통제하기 쉽다는 것이 우리의 설계 판단입니다.

X 게시물의 수·인기·배지는 진실의 라벨이 아닙니다. 당사자의 발표는 ‘그렇게 발표했다’는 직접 근거일 수 있지만, 그 발표 내용의 실재 여부는 추가 자료가 필요할 수 있습니다. 서로 다른 게시물이 같은 보도자료를 재전송한 경우 **문서 수와 출처 독립성**을 분리합니다.

## 접근 범위와 비용

공식 X 문서상 Post read는 현재 **반환 자원당 $0.005**입니다. 가상으로 50건×20개 게시물=1,000개의 과금 대상 read라면 $5입니다. 이는 추가 프로필·별도 호출·모델 추론 비용을 제외한 예시이며, 실제 비용은 응답·과금 기록으로 집계합니다. 최근 7일 밖의 주장은 recent search만으로 찾을 수 없으므로 과거 게시물 검색 접근 범위도 확인해야 합니다. 도구 접근권이 있다는 말과 무료라는 말은 다릅니다.

웹 검색 공급자의 단가를 이번에 동일 조건으로 확정하지는 않았으므로 현재 금액 비교표는 만들지 않습니다. **API별 실제 비용·반환 문서 수·추출 비용·LLM 토큰**을 구분해 기록합니다.

## 실험에서 통제할 사항

- **C1 → C2:** 같은 초기 근거·순서·모델로 시작합니다. 외부 search와 URL fetch를 별도 로그로 남깁니다.
- **도구 선택은 에이전트:** `search_x`, `search_web`, `fetch_url`, 도메인별 `query_official` 등의 읽기 도구 후보입니다. 미리 모든 도구의 호출 순서를 강제하지 않습니다.
- **추가 정보와 판단의 효과 분리:** C2 안에서 고정 검색 정책과 적응형 정책도 같은 예산으로 비교합니다.
- **시간:** claim reference date, 문서 발행 시점, 조회 시점, API 질의 기간을 보존합니다. 이후 문서를 허용할지 평가 전에 정합니다.
- **재현성:** 허용되는 범위의 응답 snapshot, URL·게시물 ID·작성자·해시·query·순위·시간·usage를 기록합니다. 같은 실행 창에서 비교하고, replay 실험과 live 실험을 구분합니다.
- **정답 누출:** gold label·해설은 도구 입력에서 제외합니다. 전문 팩트체크 정답 페이지의 허용 여부도 정해 모든 조건에 동일하게 적용합니다.
- **평가와 보류:** API 오류·접근 제한과 의미적 근거 부족을 구분합니다. 외부 API 응답을 곧바로 정답으로 삼지 않습니다.
