# Task A — 지표 정의와 평가 예시

주요 지표와 추가 진단 지표의 초안입니다. 수치는 모두 가상 예시입니다.

**화면의 모든 숫자는 가상 10건입니다.** 변형 조건의 C1 판정은 **정답 6·오답 4**, 이 중 **근거까지 갖춘 정답은 5건**입니다. C2가 오답 2건을 회복하고 정답 1건을 손상시키면 정답은 **6+2−1=7건**입니다. 청중에게는 ① 6건과 5건의 차이, ② 회복과 손상의 분모 차이를 먼저 설명합니다.

| 지표 | 수식 | 같은 예시를 읽는 방법 |
|---|---|---|
| **근거 동반 성공률(Grounded Success Rate, GSR)** | $GSR(c,e)=\frac{1}{N_{c,e}}\sum_i \mathbf{1}[V_i\land E_i\land T_i]$ | $V$는 판정 정답, $E$는 인용 근거의 충분성, $T$는 시점·범위의 일치입니다. 조건 $(c,e)$의 채점 대상 시도 10건 중 세 조건을 모두 충족한 것은 5건이므로 **5/10=50%**입니다. |
| **근거 변형에 따른 C1 GSR 하락** | $D_e=GSR(C1,충분)-GSR(C1,e)$ | 같은 10개 주장으로 충분 조건에서 8건, 변형 조건에서 5건 성공하면 **80%−50%=30%포인트**입니다. 누락·충돌·일관된 오도 각각을 별도로 비교합니다. 값이 음수이면 변형 조건의 GSR이 더 높았다는 뜻입니다. |
| **판정 회복률(Recovery Rate)** | $R=\#(C1\ 오답\land C2\ 정답)/\#(C1\ 오답)$ | 처음 틀린 4건 중 2건이 정답으로 바뀌어 **2/4=50%**입니다. |
| **판정 손상률(Harm Rate)** | $H=\#(C1\ 정답\land C2\ 오답)/\#(C1\ 정답)$ | 처음 맞힌 6건 중 1건이 오답으로 바뀌어 **1/6≈16.7%**입니다. 두 전이율은 분모가 다릅니다. 전체 정확도 차이는 **(2−1)/10=10%포인트**입니다. |
| **조건별 외부 검색률(External Search Rate)** | $S_e=\#(e에서\ 외부검색\ 1회\ 이상인\ 사례)/\#(e의\ 사례)$ | C2의 같은 조건 10건 중 6건이 외부 검색을 했다면 **6/10=60%**입니다. 한 사례에서 세 번 검색해도 분자에는 한 건으로 셉니다. |

**교수님이 채점 기준을 물으시면**

- **무엇을 정답으로 삼나요?** 실험 전에 대상 시점·허용 자료·판정·필수 사실을 사람이 검수합니다. 같은 사실을 입증하는 대체 출처도 인정합니다. 실제로 ‘근거 부족’이 정답이면 확인한 범위와 빠진 결정적 정보가 적절한지 채점합니다. 참조 정답을 아직 확정하지 못한 사례는 검수 보류로 따로 기록합니다.
- **불완전한 C1에 불공정한가요?** 원 주장에 대한 GSR은 각 환경에서 **최종 과제를 달성한 비율**입니다. 결정적 근거가 제거되어 정답 입증이 불가능했던 경우에는 **보류했는지**를 별도로 기록합니다. 이때의 GSR 하락에는 정보 접근 제약도 들어갑니다.
- **실행 실패는 어떻게 세나요?** GSR의 분모는 미리 채점 대상으로 정한 사례의 전체 시도이며 실행 실패는 성공 0건입니다. 회복·손상은 **C1·C2에서 모두 정상 판정을 얻은 쌍** 안에서 계산하고, 전체 시도 대비 유효 쌍 수와 실행 실패 수를 병기합니다. 분모가 0이면 N/A입니다. 외부 검색률은 조건별 전체 시도에서 실제 호출 로그를 사용하고, 판단 전에 실패한 실행 수도 적습니다.
- **검색기가 가짜 문서를 걸렀나요, 모델이 읽고도 채택하지 않았나요?** 코퍼스에 오도 문서를 심은 사례 중 실제 top-k에 들어온 비율을 **노출률**로 봅니다(가상 예: 10건 중 7건이면 70%). 노출 7건 중 최종 이유가 그 거짓 내용을 판정 근거로 사용한 사례가 3건이면 **노출 후 채택률은 3/7≈42.9%**입니다. 반박하려고 인용한 경우는 채택에서 제외합니다.
- **검색을 많이 하면 좋은가요?** 검색률은 행동을 설명합니다. 검색 후 품질이 좋아졌는지는 GSR·회복·손상으로 보고, 비용은 총 외부 호출 수를 사례 수로 나누어 함께 봅니다. C2 안에서 **같은 모델·도구·예산**의 고정 검색 절차와 적응형 정책을 비교해야 추가 정보 접근과 검색 판단의 효과를 구분할 수 있습니다.


## 추가 후보의 정의

| 지표 | 정의 | 가상 예시 |
|---|---|---|
| Accuracy | 정확한 판정 수 / 전체 사례 | 7/10=70% |
| Macro-F1 | 클래스별 2PR/(P+R)의 평균 | 두 클래스 F1 .8, .6 → .7 |
| Recall@k | 상위 k에서 찾은 gold 근거 단위 수 / gold 근거 단위 수 | 2/3≈66.7% |
| Precision@k | 상위 k 중 관련 근거 수 / 실제 반환 수 | 3/5=60% |
| Citation recall | 인용 근거가 지지하는 검증 가능한 답변 진술 / 전체 검증 가능한 진술 | 3/4=75% |
| Citation precision | 해당 진술을 지지하거나 공동 지지에 필요한 인용 / 전체 인용 | 4/5=80% |
| Independent-evidence yield | 검색 사례 중 초기 근거와 독립된 유효한 근거를 1개 이상 확보한 사례 / 검색 사례 | 3/6=50% |
| False adoption | 오도 근거 노출 사례 중 오도 내용을 판정 근거로 채택한 사례 / 노출 사례 | 3/7≈42.9% |
| Mean calls / tokens / latency / dollars | 각 자원의 총량 / 전체 시도 | 20 calls/10=2 calls |
| Failure rate | 정상 판정 없이 종료된 기술적 실패 시도 / 전체 시도 | 1/10=10% |
| Cost per recovery | 평가 집합의 C2 추가 총비용 / C1 오답→C2 정답 사례 수 | $1/2=$0.50 |
| Premature stop | 사전 정의한 추가 검증 예산 안에서 회복 가능하나 오답 종료한 사례 / 평가 가능한 종료 사례 | replay로 판정; 미확인 상태는 별도 |
| Redundant search | 해당 검색을 제거해도 근거 동반 정답이 유지되는 것으로 판정된 호출 / 평가 가능한 검색 호출 | 2/8=25%; replay 조건 명시 |
| Tool-selection accuracy | 주석된 적절한 도구 집합에 속한 선택 / 도구 선택을 평가한 상태 | 8/10=80%; 복수 정답 허용 |
| ROC-AUC | 임의의 정답 상태가 오답 상태보다 높은 점수를 받을 확률(동점 .5) | .8은 정답률 80%라는 뜻이 아님 |
| ECE | Σ_b (n_b/N) × abs(평균 예측확률_b − 실제 정답률_b) | 단일 bin의 p=.8, 정답률=.6 → .2 |
| Brier score | 평균 (p−y)² | p=.8,y=1 → .04 |
| Coverage / risk | 답변 사례/전체; 답변 중 오답/답변 사례 | 8/10=.8; 2/8=.25 |
| Sample efficiency | 같은 성능에 도달하는 학습 trajectory 수 또는 학습량별 평가 곡선 | 실제 학습 후 비교 |
| Seed variance | 여러 학습·실행 seed에서 지표 평균과 표준편차 | 동일 평가 집합으로 계산 |

**RL 보상 초안:** r=αG−βC−γH. G는 terminal grounded success, C는 정규화한 획득 비용, H는 초기 정답을 오답으로 손상시킨 지시값입니다. 실제 구현에서는 단계 비용과 종료 보상의 배치·discount를 정하고 중복 보상을 피합니다. gold는 학습/평가에만 사용하고 정책의 관측에는 주지 않습니다. 보상값과 최종 검증 성능을 각각 보고합니다.

**집계 원칙:** 같은 주장 변형은 paired case이며 독립 표본 수를 늘리지 않습니다. bootstrap을 쓴다면 base claim/event 단위로 재표집합니다. 50개 평가는 소규모이므로 비율 옆에 분자·분모를 함께 적습니다. gold 근거는 허용 가능한 대체 근거를 포함하는 주석 정책으로 정의합니다. 결정적 정보가 초기 코퍼스에 없으면 corpus-available recall과 최종 gold recall을 구분합니다. 비용 0·회복 0 등의 정의 불가능한 나눗셈은 N/A입니다.
