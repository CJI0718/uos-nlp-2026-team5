## 01. 먼저 설명할 평가의 전체 구조

### Q01. 교수님께 30초 안에 평가 계획을 어떻게 설명하나요?

> **같은 원자적 주장에 근거 조건을 바꾸어 제시하고, C0·C1·C2의 판정 정확성, 근거를 갖춘 성공, 외부 검증의 회복·손상, 자원 사용량을 비교하겠습니다. 정답과 근거 채점표는 실험 전에 고정하고, 변형 사례들은 원주장 단위로 묶어 분석하겠습니다.**

입력은 주장·판정 기준시점·허용 근거 환경입니다. 출력은 **판정, 인용 문서와 구절, 판정 이유, 검색·종료 기록**입니다. 예를 들어 “A기관은 2022년 설립되었습니다”라는 주장에 ① 2010년을 명시한 유효 근거, ② 설립 연도를 뺀 근거, ③ 2010년과 2022년이 충돌하는 근거, ④ 여러 문서가 일관되게 2022년이라고 말하는 오도 근거를 제공합니다. 기준 정답은 별도 검수한 설립 기록에 따라 **거짓**으로 유지합니다.

**에이전트의 판단**은 추가 검색 여부·검색어·도구·종료에서 드러납니다. 단순 정답률 외에 C2의 교정 효과와 실제 비용을 측정해야 이 판단의 가치를 평가할 수 있습니다. 이 예시의 기관·수치·실험 결과는 모두 가상입니다.

### Q02. 무엇을 주지표로 정할 건가요?

**권고안은 판정 Macro-F1을 주지표로, GSR을 핵심 보조지표로 두는 것입니다.** “근거 있는 검증”이 과제 성공의 최우선 기준이라는 피드백이면 GSR을 주지표로 올리고 Macro-F1을 보조로 둘 수 있습니다. 두 점수를 합쳐 임의의 가중 총점으로 만들지는 않습니다.

| 역할 | 측정값 | 연구 질문과의 연결 |
|---|---|---|
| 주지표 권고 | Verdict Macro-F1 | 참·거짓 등 각 정답 클래스에서 균형 있게 판정하는가 |
| 핵심 보조 | Grounded Success Rate, GSR | 정답에 충분하고 유효한 인용 근거와 올바른 시점·범위가 동반되는가 |
| 강건성 | 정상 대비 조건별 성능 하락 | 근거 누락·충돌·오도가 성능을 얼마나 바꾸는가 |
| 검증 효과 | Recovery, Harm, 순 정확도 변화 | C2가 C1을 고치거나 손상시키는가 |
| 효율성 | calls, tokens, USD, latency | 개선에 필요한 자원은 얼마인가 |
| 진단 | retrieval recall, 노출·채택, citation scores | 검색·읽기·판정 중 어디서 실패했는가 |

**주지표·주 비교·집계 방식은 결과를 보기 전에 고정**합니다. 선행연구는 판정과 근거를 결합하거나 분리해 평가합니다. 우리의 주지표 선택은 연구 목적에 따른 설계 선택입니다. [S1, S2, S3, S4, S6]

### Q03. C0·C1·C2에서 공정하게 비교할 수 있는 것은 무엇인가요?

| 조건 | 접근 가능한 정보 | 주요 해석 |
|---|---|---|
| C0 | 주장, 기준시점; 외부 자료 없음 | closed-book 판정 기준선 |
| C1 | 고정 코퍼스에서 검색한 초기 근거 | 주어진 근거 환경에 대한 강건성 |
| C2 | C1과 같은 초기 근거 + 외부 fetch | 추가 정보 접근과 검증 과정의 결합 효과 |

**판정은 공통 비교**, **근거 동반 성공은 C1/C2 중심 비교**로 둡니다. C0에 외부 근거 인용을 요구하여 GSR 0점을 주는 비교는 목적에 맞지 않습니다. C0 판정이 맞아도 학습 데이터에 해당 사실이 들어 있었다는 증명은 아닙니다.

C1→C2의 차이는 추가 정보 접근까지 포함합니다. **적응적 의사결정 자체의 효과**를 주장하려면 C2 내부에 같은 도구·최대 예산의 고정 검색 workflow를 두고 비교합니다. C1과 C2의 초기 문서·순서·내용은 캐시로 동일하게 맞춥니다.

### Q04. N은 50인가요, 200인가요, 실행 횟수인가요?

기본 단위는 **원주장** $i$입니다. $e$는 근거 조건, $c$는 C0/C1/C2, $r$은 반복 실행입니다. 조건 하나의 분모 $N_{c,e}$는 그 조건에서 사전에 지정한 평가 사례 수입니다. 같은 주장 50개에 조건 4개를 만들면 200개 조건 사례이지만 **독립 주장 200개**가 되지는 않습니다.

변형 수가 주장마다 다를 때는 많은 변형을 가진 주장이 평균을 지배하지 않도록 원주장별 평균을 먼저 냅니다. 비선형 지표인 Macro-F1은 별도의 조건별 confusion matrix로 계산하며, 주장별 F1을 평균하지 않습니다. C0는 근거 조건이 없으므로 같은 C0 결과를 4개의 독립 실행처럼 세지 않습니다.

## 02. 정답·보류·채점의 기준

### Q05. 참은 어디에 있나요? 모델과 검색 중 무엇을 정답으로 삼나요?

**실험 전에 사람이 검수한 reference record가 평가 기준입니다.** 모델의 사전 지식이나 실시간 검색 첫 결과가 정답을 정의하지 않습니다.

| gold 필드 | 기록 예시 |
|---|---|
| claim_id / family_id | 동일 사실·사건에서 나온 변형들을 연결 |
| atomic_claim | 주체·관계·대상·시점이 명확한 한 판정 대상 |
| target_period / evidence_cutoff | 어떤 시기의 사실을 어떤 시점까지 공개된 자료로 판단하는가 |
| gold_label / rationale | 참·거짓 등 정답과 판정 이유 |
| evidence_units / sufficient_sets | 필요한 사실 단위와 하나 이상의 충분한 근거 집합 |
| source_url / passage / version | 원문 구절, 날짜, 버전·해시, 보관 가능한 스냅샷 |
| provenance_group | 같은 보도자료·원자료를 재전재한 출처 묶음 |
| annotation / adjudication | 독립 주석과 불일치 조정 결과 |

Agent에는 gold label·정답 설명·채점표를 보내지 않습니다. 검색 가능한 자료에 정답을 뒷받침하는 문서가 있는 것과 정답지를 프롬프트로 주는 것은 다릅니다. **정답 자료도 절대적 진리 선언이 아니라, 명시한 범위에서 재검토 가능한 검수 기준**입니다. [S1, S2]

### Q06. 근거를 일부러 빼면 정답도 ‘근거 부족’으로 바뀌나요?

**이 실험에서는 원칙적으로 바꾸지 않습니다.** 세계의 사실에 대한 참·거짓과, 현재 받은 자료만으로 판정 가능한지를 별도 축으로 기록합니다.

예: 실제 설립 연도가 2010년이라는 gold는 그대로인데 C1의 문서에서 설립 연도를 지우면, 주장 “2022년 설립”의 gold는 여전히 거짓입니다. 다만 현재 근거는 불충분합니다. C1이 보류하면 **신중한 행동**으로 진단할 수 있지만 **최종 사실 판정 성공**으로 세지는 않습니다.

FEVER의 NEI처럼 특정 코퍼스에 상대적인 라벨을 쓰는 별도 Task라면 정의가 달라집니다. 그때에는 조건별 gold를 다시 정의해야 하며, 고정된 참·거짓 gold로 계산한 회복률과 혼합하면 안 됩니다. [S1, S2]

### Q07. ‘근거 부족’, ‘보류’, ‘API 실패’는 어떻게 구별하나요?

| 구분 | 의미 | 예시 |
|---|---|---|
| gold NEI | 지정한 판정 범위에서 정답 자체가 근거 부족 | 제한한 자료·cutoff로 지지/반박 불가 |
| abstain | 시스템이 판정을 유보한 정상 행동 | “현재 근거로 결론을 내리기 어렵습니다” |
| execution failure | 정상 결과를 내지 못한 기술적 종료 | timeout, 429, 파싱 실패 |

**권고 기본 평가군은 검수된 참·거짓 주장**으로 두고, 모델의 보류는 행동 필드로 저장합니다. 진짜 NEI 사례를 넣는 확장 평가군에서는 3-class로 별도 집계합니다. NEI와 보류를 같은 문자열로 저장하지 않습니다. 기술적 실패에도 명확한 상태 코드를 남깁니다.

### Q08. 사람 평가가 주관적이라는 질문에는 어떻게 답하나요?

두 사람이 모델·조건 이름을 가린 결과를 독립 채점하고, 세 번째 사람이 불일치를 조정하는 방식을 권고합니다. **조정 전 일치도**를 보고하고, 최종 정답은 조정 결과로 확정합니다. 개발 사례로 채점표를 다듬은 뒤 평가용 답변에 적용합니다.

두 주석자와 명목형 항목에 대한 Cohen's kappa는 다음과 같습니다.

$$\kappa=\frac{p_o-p_e}{1-p_e},\qquad p_e=\sum_{k}p_{A,k}p_{B,k}$$

$p_o$는 실제 일치율, $p_e$는 두 주석자의 주변 비율로 계산한 우연 일치율입니다. 가령 $p_o=.90$, $p_e=.50$이면 $\kappa=.80$입니다. 세 명이 모두 독립 주석하면 Fleiss' kappa 등 설계를 바꾸어 선택합니다. 한 클래스가 거의 전부이면 kappa 해석이 불안정하므로 원시 일치율·클래스 분포·불일치 표도 제시합니다. FEVER의 사람 주석과 ALCE의 인간 검증은 이런 평가 신뢰성 점검을 참고할 사례입니다. [S1, S3, S6]

## 03. 판정 성능의 산식

### Q09. Accuracy와 Macro-F1은 정확히 어떻게 계산하나요?

$$\mathrm{Accuracy}=\frac{\sum_{i=1}^{N}\mathbf{1}[\hat y_i=y_i]}{N}$$

클래스 $k$를 양성으로 보는 one-vs-rest 방식으로 $TP_k,FP_k,FN_k$를 셉니다.

$$P_k=\frac{TP_k}{TP_k+FP_k},\quad R_k=\frac{TP_k}{TP_k+FN_k},\quad F1_k=\frac{2TP_k}{2TP_k+FP_k+FN_k}$$

$$\mathrm{MacroF1}=\frac{1}{K}\sum_{k=1}^{K}F1_k$$

**Macro-F1은 클래스별 F1의 평균**입니다. 평균 precision과 평균 recall을 먼저 구해 F1을 계산하는 것이 아닙니다. $K$는 평가 전 고정한 gold 클래스 수입니다. [S6]

### Q10. 숫자 하나로 직접 계산해 보면요?

정상 응답 10건의 가상 confusion matrix입니다.

| gold \ prediction | 참 | 거짓 | 합계 |
|---|---:|---:|---:|
| 참 | 4 | 1 | 5 |
| 거짓 | 2 | 3 | 5 |

Accuracy는 $(4+3)/10=.70$입니다. 참 F1은 $8/(8+2+1)=8/11\approx.7273$, 거짓 F1은 $6/(6+1+2)=6/9\approx.6667$입니다. 따라서 **Macro-F1은 약 .6970**입니다.

정확도는 사례당 같은 가중치를 주고, Macro-F1은 클래스당 같은 가중치를 줍니다. 참이 90%인 데이터에서 모두 참이라고 하면 Accuracy는 .90이어도, 거짓을 잡는 능력은 0입니다. Macro-F1도 표본 구성에 영향을 받으므로 클래스별 성능·개수와 confusion matrix를 함께 보여줍니다.

### Q11. 실패하거나 보류한 건을 F1에서 빼도 되나요?

빼는 경우에는 **유효 응답 subset의 지표**라고 표시하고 coverage를 반드시 붙여야 합니다. 본 문서는 다음 두 보기를 권고합니다.

1. **전체 시도 Accuracy·GSR·실패율:** 사전에 정한 전체 $N$을 분모로 사용하고 실패/참·거짓 판정 보류의 정답 기여는 0으로 둡니다.
2. **전체 시도 Macro-F1(확장 scorer):** gold $K$개 클래스만 평균하되 실패·보류는 `INVALID/ABSTAIN`으로 저장합니다. 해당 gold 클래스의 FN에는 포함하고, 어떤 gold 클래스의 TP로도 세지 않습니다. 이를 정상 응답 subset의 표준 Macro-F1과 별도로 보고합니다.

일반 라이브러리의 `labels`, `zero_division` 설정과 결과를 손계산 fixture로 검증합니다. **실패를 임의의 참·거짓 라벨로 치환하면 FP까지 왜곡**됩니다. 특정 slice에 gold 클래스가 전혀 없으면 그 slice의 support를 명시하고, 고정 $K$·0처리 규칙으로 계산한 값인지 또는 해당 slice에서 미보고한 것인지 고정합니다. [S6]

## 04. 근거를 갖춘 성공과 인용

### Q12. GSR은 어느 논문에서 가져온 공식 지표인가요?

**우리 Task에 맞춘 제안 지표입니다.** 판정과 근거를 함께 평가하는 발상은 FEVER·AVeriTeC를 참고하되, GSR을 두 벤치마크의 공식 점수와 동일시하지 않습니다.

$$GSR(c,e)=\frac{1}{N_{c,e}}\sum_i V_iE_iT_i$$

세 값은 0 또는 1입니다. $V$는 verdict correctness, $E$는 evidence validity and sufficiency, $T$는 temporal/scope consistency입니다. **세 조건을 모두 만족해야 1**입니다. API 실패는 0이며, 검수된 전체 평가 시도가 분모입니다. 가령 판정 7건이 맞아도 근거와 시점까지 맞은 것이 5건이면 Accuracy 70%, GSR 50%입니다.

이는 성공 사건의 교집합 빈도입니다. 곱셈은 조건들의 독립성을 가정하는 확률 곱이 아닙니다. [S1, S2]

### Q13. V·E·T를 실제로 무엇을 보고 채점하나요?

| 항목 | 1점 기준 | 0점 사례 |
|---|---|---|
| V | 선언한 판정이 gold와 일치 | 거짓 주장을 참으로 판정 |
| E | 인용 대상·구절이 확인되고, 필요한 사실을 충분히 지지하며, 검수 기준상 유효함 | 가짜 문서를 근거로 채택, 존재하지 않는 인용, 핵심 정보 누락 |
| T | 대상 시점·정보 cutoff·인물/기관·지역·단위·범위가 주장과 일치 | 2024년 자료로 2020년 수치를 단정, 다른 기관 자료 사용 |

E는 **문서와 설명의 의미적 지지**에 더해 **근거 자체의 유효성**을 요구합니다. T는 틀린 시점·범위 사용을 별도 진단하려고 분리한 것입니다. 일부 E/T 실패가 중첩되어도 GSR에서는 한 사례를 한 번만 실패로 셉니다. E/T 중복이 부담되면 E에 통합한 2조건 점수를 선택할 수 있으나, 주 평가 정의는 실행 전에 고정해야 합니다.

시간 문제가 없는 stable 사례도 T를 생략하지 않고 대상·범위를 확인합니다. 확인 가능한 결과가 없으면 GSR 기여는 0이며 `not_assessable` 이유도 별도로 남깁니다.

### Q14. 정답을 맞혔는데 가짜 근거를 인용하면요?

가상 gold: A기관 설립은 2010년. 주장: “2022년 설립”.

| 출력·인용 | V | E | T | GSR 기여 |
|---|---:|---:|---:|---:|
| “거짓, 2010년 설립” + 검수된 설립 기록 | 1 | 1 | 1 | 1 |
| “거짓” + 설립일 없는 활동 소개 | 1 | 0 | 1 | 0 |
| “거짓, 2010년 설립” + 위조된 문서 | 1 | 0 | 1 | 0 |
| “거짓” + 다른 동명 기관의 설립 기록 | 1 | 0 | 0 | 0 |
| “참, 2022년 설립” + 그럴듯한 오도 문서 | 0 | 0 | 1 | 0 |

마지막 행은 **문서-답변 entailment가 높아도 사실 검증은 실패**할 수 있음을 보여줍니다. 오도 문서를 “이 문서는 틀렸습니다”라고 반박하기 위해 인용한 경우에는 허위 근거 채택으로 세지 않습니다.

### Q15. FEVER score와 AVeriTeC score는 GSR과 어떻게 다른가요?

**FEVER(2018)**는 판정만 맞히는 정확도와, 필요한 정답 근거 집합까지 회수하는 성공을 구분합니다. 지지·반박에는 하나의 완전한 정답 근거 집합이 중요하고, NEI의 처리도 별도입니다. 공식 shared-task scorer에는 근거 출력 제한 등 구현 조건이 있으므로 이름만 가져와 쓰지 않습니다. [S1]

**원 AVeriTeC(2023)**는 판정과 검색된 QA 근거의 품질을 결합하며, Hungarian matching과 METEOR 기반 근거 평가를 사용합니다. 원 논문의 대표 설정은 근거 점수 임계값 .25입니다. **후속 AVeriTeC/FEVER shared task에는 Ev2R 기반 평가가 도입되어 버전별 규칙이 다릅니다.** 우리 GSR에 .25를 그대로 이식할 이유는 없습니다. [S2, S8]

우리가 가져오는 것은 **“맞는 판정 + 적절한 근거”의 공동 평가 원리**입니다. 문서 오염·시간/범위를 위한 사람 rubric은 우리 실험에 맞게 명시합니다.

### Q16. Citation recall과 retrieval recall은 같은 건가요?

**아닙니다. 분모가 다릅니다.** Retrieval recall은 찾아야 할 gold 근거 중 얼마나 회수했는지, citation recall은 생성한 검증 가능 진술 중 얼마나 인용으로 뒷받침했는지를 봅니다.

ALCE 방식의 핵심을 단순화하면, 출력 진술 집합 $S$, 진술 $s$의 인용 집합 $C_s$, 공동 지지 판정 $\phi$에 대해 다음과 같습니다.

$$\mathrm{CitRecall}=\frac{\sum_{s\in S}\mathbf{1}[C_s\ne\varnothing\ \land\ \phi(C_s,s)=1]}{|S|}$$

ALCE는 공동 지지 여부와 개별 인용의 기여를 평가합니다. 예를 들어 4개 진술 중 3개가 충분히 인용으로 지지되면 recall은 75%입니다. **우리 적용에서는 답변을 판정·결정적 사실·짧은 설명으로 제한**하고, 진술 분할 규칙을 고정합니다. [S3, §3.3·Figure 3]

### Q17. Citation precision과 사실적으로 유효한 인용은 어떻게 구별하나요?

ALCE를 참고한 precision은 **진술을 지지하거나 공동 지지에 기여하는 인용 / 전체 인용 링크**로 해석합니다. 같은 URL을 서로 다른 진술에 붙였다면 각각의 연결을 평가합니다. 전체 인용 집합이 진술을 지지하는지부터 확인하고 개별 인용의 기여를 봅니다. [S3]

우리 실험에는 별도로 다음 진단값을 제안합니다.

$$\mathrm{ValidCitationRate}=\frac{\#\text{허용 시점·출처·내용 검수까지 통과한 인용 링크}}{\#\text{전체 인용 링크}}$$

이는 **우리 제안 지표**이며 ALCE 공식 precision의 이름을 대신하지 않습니다. 인용 5개 중 의미적 지지 4개, 사실적 유효성까지 통과한 것이 3개라면 각각 80%, 60%입니다. 인용이 없으면 비율은 N/A, `no_citation_rate`는 별도 보고하며 근거 필수 Task의 GSR은 0입니다.

### Q18. gold와 다른 URL을 찾으면 틀린 근거인가요?

**동일 사실을 충분히 입증하는 대체 근거도 허용합니다.** URL 일치와 사실 단위의 충족을 구분합니다. 새 대체 근거는 조건·모델명을 가리고 검수한 뒤 모든 시스템에 동일 기준으로 반영합니다. 검색 결과를 보고 한 모델에게만 유리하게 gold를 확장하지 않습니다.

Ev2R은 자동 근거 평가에서 표면적 일치, 복수의 유효 근거 경로, 시간 제약 등의 문제를 다룹니다. 우리는 이를 **문자열 유사도만으로 근거 성공을 결정하지 않는 근거**로 참고합니다. 자동 Judge를 곧바로 정답 판정자로 삼지 않고, 작은 평가군에서는 사람 검수와 대조합니다. [S8, §3·§5.2]

## 05. 검색 성능과 오염의 영향

### Q19. C1에서 직접 문서를 주는 것과 검색시키는 것은 어떻게 평가하나요?

| 설정 | 통제하는 것 | 평가 가능한 능력 |
|---|---|---|
| 지정 evidence 직접 입력 | 문서 내용·수·순서 | 근거 해석과 판정; retrieval 성능은 제외 |
| 주장별 pool 안에서 검색 | 후보군·오염률 + 검색기 | 제한된 후보에서 선택·판정 |
| 공통 fixed corpus에서 검색 | 모든 주장이 공유하는 DB | 실제 retrieval+판정의 end-to-end 성능 |

주 연구를 공통 fixed-corpus RAG로 두고, 지정 근거 입력을 **검색 실패와 읽기 실패를 구분하는 보조 실험**으로 사용할 수 있습니다. BM25·dense retrieval 비교는 정책·모델을 고정하고 수행합니다. 직접 입력 조건의 성공률을 retrieval 성능이라고 부르지 않습니다.

### Q20. Recall@k와 Precision@k의 분모는 무엇인가요?

중복 제거한 상위 $k$ 검색 결과를 $R_i^k$, 유효하고 관련 있는 gold 근거 단위를 $G_i$라 하면:

$$\mathrm{Recall@k}_i=\frac{|R_i^k\cap G_i|}{|G_i|},\qquad \mathrm{Precision@k}_i=\frac{|R_i^k\cap G_i|}{k}$$

gold 3개 중 2개를 top-5에서 찾으면 recall은 $2/3$, precision은 $2/5$입니다. k보다 적게 반환하는 경우 **표준 P@k는 분모 k를 유지**하고 빈 자리는 비관련으로 처리합니다. 실제 반환 수로 나눈 값은 **Returned-set precision**이라는 별도 이름으로 표기합니다. 예전 초안의 두 정의 혼용은 이렇게 정리합니다. [S6, IR 표준 정의를 본 실험에 적용]

$G_i$가 빈 경우 Recall@k는 N/A입니다. 오염 문서가 주장과 단어상 관련 있어도 **유효 gold 근거**는 아닙니다. 사실 단위로 매핑할 때에는 같은 문서의 여러 중복 chunk를 여러 정답으로 세지 않도록 단위를 고정합니다.

### Q21. 정답 문서 하나만 찾으면 충분한가요? 순위도 봐야 하나요?

여러 문서를 결합해야 하는 주장은 충분한 근거 집합의 회수를 봅니다. 가능한 충분 집합들의 모음을 $\mathcal G_i$라 두면:

$$\mathrm{CompleteSetHit@k}_i=\mathbf{1}[\exists G\in\mathcal G_i:\ G\subseteq R_i^k]$$

이는 FEVER의 완전 근거 집합 원리를 참고한 진단값입니다. 동일 사실을 입증하는 대체 집합들을 전부 찾아야 하는 것은 아닙니다. [S1]

순위 자체가 연구 요인이면 relevance grade $rel_j$에 대해 $DCG@k=\sum_{j=1}^{k}(2^{rel_j}-1)/\log_2(j+1)$, $nDCG@k=DCG@k/IDCG@k$를 추가할 수 있습니다. relevance를 단순 주제 관련성으로 줄지, 유효 근거성으로 줄지 고정합니다. IDCG=0이면 N/A입니다. 첫 실험에서는 Recall@k·완전 집합 회수만으로도 주요 실패를 분리할 수 있습니다.

### Q22. 코퍼스 오염률·노출률·채택률은 어떻게 다른가요?

$$\rho=\frac{\#\text{코퍼스 내 오염 문서}}{\#\text{코퍼스 전체 문서}}$$

$$\mathrm{Exposure}=\frac{\#\text{실제 모델 입력에 오도 내용이 포함된 사례}}{\#\text{오염 문서를 심은 평가 사례}}$$

$$\mathrm{FalseAdoption\mid Exposure}=\frac{\#\text{노출 후 오도 사실을 판정 근거로 채택한 사례}}{\#\text{노출 사례}}$$

코퍼스 100문서 중 20문서가 오염되면 $\rho=20\%$입니다. 평가 10건 중 7건에서 실제 prompt에 오도 내용이 들어갔고 그중 3건이 채택했다면, 노출률 70%, 조건부 채택률 $3/7\approx42.9\%$입니다. **top-k 선정 → snippet 절단 → 최종 prompt 포함**을 따로 기록하면, 검색됐지만 모델은 못 본 문서를 노출로 잘못 세지 않습니다.

오도 내용을 반박하기 위한 인용은 채택이 아닙니다. 노출률이 낮아 안전한 것인지, 읽고도 견딘 것인지 분리합니다. 조건부 채택률은 선택된 노출 사례의 통계이므로 그 값만으로 모델의 전체 강건성을 비교하지 않습니다.

### Q23. ‘정상 대비 성능 하락’은 어떤 수식인가요?

지표 $M$이 클수록 좋을 때, 같은 원주장의 충분 조건 $e_0$와 오염 조건 $e$를 비교합니다.

$$D_e=M(C1,e_0)-M(C1,e)$$

GSR이 80%에서 50%이면 하락은 **30%포인트**입니다. 상대 감소율은 $(.80-.50)/.80=37.5\%$로 다른 값입니다. $D_e<0$이면 해당 조건에서 오히려 개선된 것입니다.

최종 결과는 충분·누락·충돌·일관된 오도별로 분리합니다. 문서 수·길이·오염 비율·순서·출처 표시·query 난이도를 한꺼번에 바꾸면 원인 해석이 어려우므로, 처음에는 한 요인씩 고정/변형합니다. 무작위 순서 seed도 기록합니다.

## 06. 능동 검증의 교정 효과

### Q24. Recovery와 Harm의 분모가 왜 다른가요?

정상 참·거짓 판정을 양쪽에서 얻은 동일 사례 쌍을 다음처럼 셉니다.

| C1 → C2 | C2 정답 | C2 오답 |
|---|---:|---:|
| C1 정답 | a: 유지 | b: 손상 |
| C1 오답 | c: 회복 | d: 지속 오답 |

$$\mathrm{Recovery}=\frac{c}{c+d},\qquad \mathrm{Harm}=\frac{b}{a+b},\qquad \Delta Acc=\frac{c-b}{a+b+c+d}$$

$a=5,b=1,c=2,d=2$라면 C1 정확도 60%, C2 70%, 회복 $2/4=50\%$, 손상 $1/6\approx16.7\%$, 순 개선 10%포인트입니다. **회복 50% − 손상 16.7%가 순 개선은 아닙니다.** 출발 집단의 크기가 다르기 때문입니다.

### Q25. 보류나 실행 실패도 회복으로 세나요?

위 전이표는 **양쪽 정상 확정 판정 subset**에 적용합니다. `valid_pair_count / all_pair_count`를 붙이고, 보류·실패→정답은 별도 전이표로 제시합니다. 실패를 “틀린 추론”으로 바꾸어 회복 수를 늘리지 않습니다.

전체 시스템 개선은 실패를 0으로 포함하는 **전체 시도 Accuracy/GSR 차이**로 별도 보고합니다. 양쪽 모두 정상인 쌍만 고르면 어려운 사례가 빠질 수 있으므로 이 차이도 함께 봅니다. 회복 대상이 0개이면 Recovery=N/A이지 0%가 아닙니다. GSR의 0→1 교정을 계산할 수도 있지만 그때에는 **Grounded recovery**로 이름을 바꾸고 verdict recovery와 섞지 않습니다.

### Q26. 검색을 많이 하면 좋은 에이전트인가요?

$$\mathrm{SearchRate}=\frac{\#\text{외부 검색을 1회 이상 시도한 사례}}{N},\qquad \mathrm{MeanCalls}=\frac{\sum_i n_{\mathrm{calls},i}}{N}$$

10건 중 6건이 검색하고 총 호출이 18회면 검색률 60%, 전체 평균 1.8회입니다. 검색한 사례당 평균은 $18/6=3$회로 다른 분모입니다. **검색률은 행동량이지 품질 점수는 아닙니다.** 검색 전 실패한 사례, 검색 시도와 성공 응답도 구분합니다.

검색 필요성은 현재 근거 상태의 충분성·충돌·출처 위험을 사전 주석한 상태에서 탐색적으로 평가합니다. “검색했다”만으로 필요 판정을 맞혔다고 보지 않습니다. 근거 부족 사례에서 검색은 합리적이어도 열린 웹에 회복 가능한 자료가 없을 수 있습니다.

### Q27. 출처 독립성과 불필요한 검색은 어떻게 채점하나요?

$$\mathrm{IndependentYield}=\frac{\#\text{검색 후 초기 근거와 독립된 유효 근거를 얻은 사례}}{\#\text{검색 사례}}$$

서로 다른 도메인이어도 같은 보도자료를 재전재했다면 같은 provenance group입니다. “독립”은 문서 개수가 아니라 원자료의 계보로 주석합니다. 계보를 확인하기 어려운 것은 unknown으로 남기고 보수적 판정과 민감도 분석을 구분합니다.

**중복 검색과 불필요한 검색은 다릅니다.** 동일 query·문서 재반환은 로그로 셀 수 있지만, 그 호출이 결과에 필요 없었는지는 제거 후 replay 같은 반사실적 비교가 있어야 합니다. 후속 문맥을 바꾸면 정책도 달라지므로 replay의 도구 응답·seed·예산을 고정합니다. 첫 실험의 필수 지표는 중복 호출률과 총비용이고, “불필요함”은 별도 분석 후보입니다.

## 07. 비용·보류·확신

### Q28. FIRE에서처럼 비용은 어떻게 계산하나요?

모델 $m$의 100만 토큰당 단가를 $p_{in,m},p_{out,m}$이라 하면, 사례 $i$의 호출별 비용을 합산합니다.

$$C_i^{LLM}=\sum_t\frac{n_{in,it}p_{in,m_t}+n_{out,it}p_{out,m_t}}{10^6}$$

$$C_i^{search}=\sum_a n_{ia}p_a,\qquad C_i^{online}=C_i^{LLM}+C_i^{search}+C_i^{other}$$

FIRE §4.4는 API LLM 비용, 공개 모델의 GPU 임대비, 검색 API 비용과 시간을 구분합니다. Table 7의 FIRE+GPT-4o-mini는 **559개 주장 전체**에 LLM $0.14, 검색 $0.20, 시간 1.25시간을 보고합니다. 이 당시 비용을 현재 가격으로 해석하지 않습니다. [S4]

우리 로그에는 입력·출력·캐시·추론 토큰 등 provider가 실제 청구한 항목, 적용 단가 날짜, 검색 API 요청 수를 기록합니다. **snippet은 다음 호출의 입력으로 비용에 반영**됩니다. 다시 보낸 문맥도 청구 규칙에 따라 계산합니다. timeout은 무료라고 단정하지 않고 실제 청구 확인 여부를 남깁니다. 색인·임베딩 구축비와 평가 Judge 비용은 온라인 추론비와 별도 표로 보고합니다.

### Q29. ‘회복 1건당 비용’과 품질-비용 trade-off는요?

$$\mathrm{CostPerRecovery}=\frac{\sum_i C^{extra}_{C2,i}}{\#\text{C1 오답}\to\text{C2 정답}}$$

추가 비용 $1로 2건을 회복하면 $0.50/건입니다. 비용 분자는 **전체 평가군에 든 추가 비용**이며 성공 사례의 비용만 골라 쓰지 않습니다. 회복 0건이면 유한한 값으로 계산할 수 없다고 표시하고 총비용·회복 0을 보고합니다.

순 회복 $c-b$로 나누는 값은 손상이 크면 0 또는 음수 분모가 되므로 첫 결과의 주지표로 쓰지 않습니다. 대신 **동일 예산에서 GSR**, **비슷한 GSR에서 비용**, **GSR–비용 산점도와 Pareto frontier**를 함께 봅니다. 같은 최대 예산과 같은 실제 지출은 다르며, 조기 종료의 절감도 보고할 가치가 있습니다. [S4를 참고한 우리 집계 제안]

### Q30. 보류하면 정확도가 높아지는 꼼수는 어떻게 막나요?

확정 판정을 내린 사례 집합 $A$에 대해:

$$\mathrm{Coverage}=\frac{|A|}{N},\qquad \mathrm{Risk}=\frac{\sum_{i\in A}\mathbf{1}[\hat y_i\ne y_i]}{|A|}$$

10건 중 8건에 답하고 그중 2건이 틀리면 coverage=.80, risk=.25입니다. 모두 보류하면 coverage=0, risk=N/A입니다. **risk만 낮다고 우수한 시스템은 아닙니다.** 전체 시도 Accuracy/GSR와 coverage–risk를 같이 보고합니다. 임계값은 개발 세트에서 정하고 테스트 결과를 보고 고르지 않습니다. 실패율은 보류율과 별도로 제공합니다.

### Q31. confidence, Brier, ECE, AUC는 어떤 때 필요한가요?

명시적인 확신도 $p_i$를 출력·기록할 때만 평가합니다. $z_i$는 실제 판정의 정답 여부입니다.

$$\mathrm{Brier}=\frac{1}{N}\sum_i(p_i-z_i)^2$$

$$\mathrm{ECE}=\sum_{b=1}^{B}\frac{|B_b|}{N}\left|\mathrm{acc}(B_b)-\mathrm{conf}(B_b)\right|$$

정답 확률을 .8이라 했는데 실제로 맞았다면 Brier 항은 .04, 틀렸다면 .64입니다. 평균 .8로 확신한 bin의 정답률이 .6이면 그 bin의 calibration gap은 .2입니다. ECE는 bin 수·경계에 민감하므로 이를 고정합니다. Brier는 calibration만이 아니라 전반적인 확률 예측 품질을 평가합니다. [S6, S7]

AUC는 정답 사례가 오답 사례보다 높은 confidence를 받는 순위 분별력입니다. **AUC .8은 정답률 80%가 아닙니다.** 정답/오답이 한 종류뿐이면 AUC는 정의되지 않습니다. LLM의 말로 표현한 확신도와 토큰 확률도 다릅니다. 표본 50개를 여러 bin으로 나누면 불안정하므로 보조 분석으로 둡니다. RL의 reward는 학습 목적 함수이며, 독립적인 최종 성능 지표를 대체하지 않습니다.

## 08. 표본·통계·실험 통제

### Q32. 50개로 유의미한 결론을 낼 수 있나요?

**통제된 탐색 실험과 오류 분석은 가능하지만 작은 차이를 정밀하게 확정하기는 어렵습니다.** 독립 이항 성공률 $\hat p$의 표준오차 근사는 $\sqrt{\hat p(1-\hat p)/N}$입니다. 50건 중 35건 성공이면 $\hat p=.70$, 표준오차 약 .0648입니다.

작은 표본에서 단순 정규 근사보다 안정적인 **Wilson 95% 구간**의 예시는 다음과 같습니다($z=1.96$).

$$\mathrm{center}=\frac{\hat p+z^2/(2N)}{1+z^2/N}$$

$$\mathrm{halfwidth}=\frac{z\sqrt{\hat p(1-\hat p)/N+z^2/(4N^2)}}{1+z^2/N}$$

35/50의 구간은 약 **56.2%–80.9%**입니다. 이는 독립 이항 지표의 예시이며 **Macro-F1이나 200개 종속 변형에 그대로 적용하지 않습니다.** 50개를 임의의 편의표본으로 모았다면 이 구간도 전체 뉴스 세계를 대표한다는 보장은 없습니다. 산식 근거는 [NIST의 비율 신뢰구간 설명](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)입니다.

### Q33. 변형·반복이 있으면 신뢰구간은 어떻게 구하나요?

**원주장 단위 paired cluster bootstrap**을 권고합니다. 원주장 ID를 복원 추출한 뒤, 선택된 주장의 모든 조건·모델·반복 기록을 함께 가져와 두 시스템의 지표 차이를 다시 계산합니다. 이 작업을 예컨대 10,000회 수행하고 차이 분포의 2.5·97.5 percentile을 보고합니다. 재표집 seed와 방식을 기록합니다.

Macro-F1은 매번 confusion matrix에서 다시 계산합니다. 같은 사건에서 여러 주장이 파생되었으면 원주장보다 상위 사건 단위를 cluster로 선택합니다. 평가 사례 변동과 모델 sampling 변동은 다른 불확실성이므로, 반복 seed별 결과도 따로 보여줍니다. 이것은 paired 검정 원리를 우리 종속 데이터 구조에 적용한 권고이며 Dror 논문의 특정 실험을 복제한 것은 아닙니다. [S5]

### Q34. C1보다 C2가 좋아졌다고 통계적으로 말하려면요?

독립 원주장 하나당 한 조건의 이진 성공 여부를 비교할 때, Q24의 불일치 쌍 $b,c$로 **exact McNemar test**를 사용할 수 있습니다. 귀무가설에서 $X\sim\mathrm{Binomial}(b+c,.5)$이며 양측 p값은 다음과 같습니다.

$$p=\min\left(1,2\Pr[X\le\min(b,c)]\right)$$

$b=1,c=2$이면 p=1입니다. **10건에서 정확도가 10%포인트 올랐다는 사실만으로 통계적 우월성을 확정할 수 없습니다.** 불일치가 0이면 검정할 차이 정보가 없습니다. 같은 주장 변형들을 독립 쌍으로 펼쳐 적용하지 않습니다. Macro-F1 차이는 paired resampling 등 그 지표에 맞는 방법으로 평가합니다. [S5]

p값은 “귀무가설이 참일 확률”이 아닙니다. 효과 크기·구간·오류 사례를 함께 보고하고, 주 비교를 미리 정합니다. 여러 조건·모델에 확증적 검정을 반복하면 Holm 등 다중 비교 보정을 정하거나 탐색 분석으로 명시합니다.

### Q35. retrieval 설정·웹 변동 때문에 결론이 흔들리지 않나요?

| 통제 항목 | 권고 기록·설정 |
|---|---|
| Retriever | BM25 tokenizer/parameters 또는 embedding 모델 ID·버전·유사도 |
| 입력 예산 | top-k, chunk/snippet 길이, 전체 evidence token budget |
| 순서 | 검색 순위·출처 순서·shuffle seed |
| Query | 원 claim, 고정 rewrite, Agent rewrite의 구분 |
| Web | query·provider·시각·raw response·URL·본문 버전 |
| Model | 정확한 ID, sampling, 출력 한도, 프롬프트, timeout |
| Gold/scorer | 버전, 채점표, 예외·0분모 처리 |

top-k 등을 개발 사례에서 정한 뒤 평가군에 고정합니다. **적응적 k/query 변경은 별도 정책 요인**으로 둡니다. 생성의 top-p와 retrieval top-k는 다릅니다. 웹 비교는 가능한 한 가까운 시각에 실행하고, 허용 범위의 결과 캐시로 replay 평가를 병행합니다. 캐시 재생과 실제 live 검색 결과는 별도 표시합니다.

### Q37. 교수님이 “지표가 너무 많다”고 하시면요?

> **주요 결과는 Macro-F1, GSR, C1→C2 회복·손상, 비용의 네 묶음으로 보고하겠습니다. Retrieval과 citation 지표는 실패 원인을 분해하는 보조표에 두겠습니다. 확신도나 RL 관련 지표는 해당 방법을 실제로 채택할 때만 추가하겠습니다.**

논문의 성능 숫자를 많이 모으는 것보다 **같은 Task·같은 표본·같은 예산에서 비교 가능한 결과**를 만드는 것이 목표입니다. 논문마다 데이터·라벨·평가 단위가 다르므로 기존 숫자와 우리의 점수를 직접 순위 비교하지 않습니다.

### Q38. “이 설계의 새로움은 metric을 새로 만드는 건가요?”

> **새 점수 자체보다, 근거 오염의 구성과 검색 노출, 오도 채택, 외부 검증의 회복·손상을 연결해서 분석하는 것이 연구의 중심입니다. 기존 지표는 최대한 유지하고, 추가 지표는 각 연구 질문을 관측 가능한 사건으로 정의하기 위해 사용합니다.**

construct validity는 “측정값이 의도한 능력을 재는가”, internal validity는 “차이가 관심 요인에서 발생했는가”, external validity는 “어디까지 일반화 가능한가”입니다. 이에 각각 **판정과 근거의 분리**, **같은 claim·초기 근거·모델의 대응 비교**, **표본 출처·시간·도메인 분포 공개**로 대응합니다.

### Q39. 다음 회의에서 무엇만 결정하면 실행 준비가 되나요?

1. **Task 라벨:** 참·거짓 기본군과 NEI 확장군의 구분; 보류 출력 정의.
2. **주 결과:** Macro-F1 또는 GSR의 우선순위, C1→C2 주 비교.
3. **근거 rubric:** E/T 기준, 대체 근거 승인, 출처 계보·시간 기준.
4. **표본 단위:** 50개 원자료에서 원자적 주장·사건 cluster를 구성하는 규칙.
5. **정보 환경:** 공통 corpus, 오염 조건, top-k·토큰 예산, C2 fetch 도구.
6. **통계·실패:** 전체 시도와 정상 쌍의 분모, seed 반복, CI·주 검정.

테스트 결과를 보기 전에 이 여섯 항목을 한 장의 protocol로 잠급니다. 개발용 사례로 **채점 예제 5–10건을 먼저 손으로 계산**하여 구현과 비교하면, 자동 scorer가 잘못된 분모를 쓰는 문제를 줄일 수 있습니다.
