# 세 경로의 정보와 근거에 따른 판단 수정

NLP 5조 · 연구 설계 제안 · 2026-11-02

**읽기 안내:** [원문 캡처를 포함한 팀 공유 HTML](팀공유_연구가이드.html) · [영어 Task·Metrics 초안](Task_Metrics_EN.md) · [Task 1장 + 문헌 15장 영어 발표 개요](Team5_Slides_EN.md). 이번 보완에서는 판정·보류·실행 실패의 분모와 근거 동반 성공의 정의를 영어 초안에 구체화했다. 아래는 연구 배경과 설계 선택지를 설명하는 한국어 원본이다.

## 1. 우리가 하려는 일을 한 사례로

가상 주장: **“A기관은 2022년에 설립됐다.”** 자료 없이 질문했을 때 모델은 2020년이라고 답한다. 처음 제공된 기사 세 개에는 모두 2022년이라고 적혀 있다. 에이전트는 기사들이 같은 블로그를 인용했는지 확인하고 기관 연혁을 찾아, 2020년은 설립이고 2022년은 이전이라는 차이를 발견한다. 최종 결과는 ‘반박’, 근거 구절, 두 연도를 혼동한 이유다.

반대 상황도 중요하다. 모델이 오래된 대표자 이름을 알고 있다면, 새 공식 임명 기록을 받아들여 답을 바꿔야 한다. 따라서 목표는 **틀린 판단은 고치고, 맞는 판단은 잘못된 자료 때문에 훼손하지 않는 것**이다. 검색 횟수와 비용도 함께 측정한다.

이 작업은 retrieval로 자료를 찾고, NLP로 주체·수치·시점·범위를 해석하며, ReAct로 다음 질의·열람·종료를 선택한다. 학부 프로젝트의 구현 중심은 한 모델과 작은 도구 집합 위에서 검증 행동을 설계하고 그 효과를 분석하는 데 둔다.

**추천 연구 질문:** 초기 자료에 오류나 시점 혼동이 있을 때, 근거의 출처·시점·주장 범위를 기록하며 추가 검증을 선택하는 정책은 일반 ReAct 및 고정 검증 절차보다 오답 교정과 정답 보존의 균형을 개선하는가?

영문 설명용 표현: **Evidence-grounded selective revision under knowledge conflicts**. 여기서 revision은 현재 작업의 판정 수정이다.

## 2. 합의한 문제의식을 학술적 용어로 연결하기

| 사용자와 합의한 관점 | 연구에서 사용할 표현 | 관찰할 대상 |
|---|---|---|
| 학습 결과로 모델이 이미 활용하는 정보 | Parametric knowledge / internal prior | 외부 자료 없는 별도 질의에 대한 응답 |
| 처음 제공된 자료 | Initial external evidence | 사용자 제공 자료 또는 초기 retrieval 결과 |
| 에이전트가 찾아온 자료 | Actively acquired evidence | 행동 이후 실제 열람한 새 자료 |
| 서로 다른 내용의 충돌 | Context–memory / inter-context conflict | 모델의 초기 응답과 자료, 또는 자료들 사이의 불일치 |
| 적절히 유지하거나 고치는 능력 | Selective revision / evidence-grounded correction | 초기 판정에서 최종 판정으로의 변화와 그 근거 |
| 더 찾아야 하는지 판단 | Active evidence acquisition / stopping decision | 다음 검색의 목표와 조사 종료 |

모델 파라미터를 θ, 주장과 기준 시점을 c와 τ, 초기 자료를 E₀라 두자. 별도의 closed-book 응답 p는 모델의 관찰 가능한 출발 상태를 기록한다. 본 실험에서는 초기 자료를 읽은 판정 a₀에서 시작하여, 정책이 고른 행동으로 E₁, E₂…를 확보하고 최종 판정 a_f를 만든다.

**관찰 경로:** p → 초기 자료 E₀를 읽은 a₀ → 추가 행동과 근거 → a_f.

초기 지식 probe p는 독립된 새 문맥에서 실행한다. 그 응답이나 정오 태그를 본 실험의 에이전트에게 다시 제공하지 않는다. 다만 모든 비교 방법에 동일한 초기 판정 a₀를 주는 ‘판정 검증·수정’ 실험을 구성할 수 있다. 이때 a₀를 공유한다는 조건을 모든 방법에 동일하게 적용한다.

이 관점은 [ClashEval](https://proceedings.neurips.cc/paper_files/paper/2024/hash/3aa291abc426d7a29fb08418c1244177-Abstract.html)의 prior/context 구분, [CRITIC](https://arxiv.org/html/2305.11738)의 도구 피드백을 통한 수정, [FIRE](https://aclanthology.org/2025.findings-naacl.158/)의 반복 검증을 연결한다.

## 3. 선행연구의 흐름과 우리 설계에 주는 의미

상세한 방법·결과·읽을 절은 [문헌검토.md](문헌검토.md)에 정리했다.

| 흐름 | 대표 연구와 확인된 결론 | 우리에게 주는 설계 원칙 |
|---|---|---|
| 내부 지식과 문맥의 선택 | Adaptive Chameleon: 그럴듯한 반대 문맥에는 쉽게 움직이지만, 기존 답을 지지하는 문맥도 함께 있으면 확인편향을 보임 | 단일 거짓 문서뿐 아니라 서로 다른 지지 방향의 자료도 구별 |
| 양방향 실패의 정량화 | ClashEval: 잘못된 문맥을 따르는 오류와 잘못된 기존 답에 머무는 오류를 함께 측정. 보정은 한 오류를 줄이면서 다른 오류를 늘릴 수 있음 | 평균 정확도와 함께 보존·교정을 각각 측정 |
| 실제 문서에 의한 갱신 | Real Documents 연구: 실제 정답 문서를 주면 기존 오답 유지가 적었지만, 바꾼 답도 틀리는 경우가 남음 | 답을 바꾼 횟수와 올바르게 고친 횟수를 분리 |
| 도구를 이용한 수정 | CRITIC: 검색·실행 등의 외부 피드백을 이용한 수정의 효과. 정답일 때만 멈추는 oracle 조건은 별도 | 정답표로 수정 여부를 결정하지 않는 실행기 |
| 충돌을 해석하는 방법 | Astute RAG: 내부·외부 지식의 출처를 보존하며 통합. Micro-Act: 비교를 세부 행동으로 분해 | 단순 ‘충돌을 생각해봐’보다 확인할 요소를 명시 |
| 언제 더 찾아볼 것인가 | FIRE, SEAC: 검색·검증의 반복과 종료 판단. BeliefRAG: 근거 상태에 따른 검색·검증·보류 | 적응적 재검색 자체를 새 아이디어로 내세우지 않고 공정한 기준선 사용 |
| 일치하는 거짓 근거 | Evidence Laundering: 같은 거짓 내용을 반복한 문서가 독립적 뒷받침처럼 작동 | 눈에 보이는 충돌이 없는 경우도 평가 |
| 반대 근거를 찾는 방법 | FVA-RAG: 초안에 반하는 근거를 찾아 검증하는 절차를 제시 | ‘반대 자료가 발견됨’과 ‘그 자료가 참임’을 구별하는 검수 |

연구 흐름은 ‘내부 지식과 자료 중 무엇을 따르는가’에서 ‘자료를 어떻게 비교하는가’, 다시 ‘무엇을 더 찾아야 하는가’로 확장되고 있다. 우리의 관심은 이 마지막 행동 단계가 **어떤 종류의 판단 변화를 낳는지**를 앞 단계의 상태와 연결하는 데 있다.

## 4. 독창성을 설명할 방향 세 가지

### A. 정답 보존과 오답 교정을 함께 보는 능동 검증 — 추천 중심

- 질문: 추가 조사로 오답을 고치면서 정답을 오염시키지 않을 수 있는가?
- Task: 주장·기준 시점·초기 자료를 받고, 추가 근거를 선택적으로 확보해 판정과 인용을 제출한다.
- 비교: 고정 검증, 일반 ReAct, 근거 상태를 기록하는 ReAct.
- 핵심 결과: 근거 동반 성공, 초기 오답 교정, 초기 정답 보존, 비용.
- 부담: 중상. 어려움은 학습보다 데이터 검수·도구 실행·공정한 비교에 있다.
- 기여의 형태: 알려진 문제를 한국어 실제 기사 기반의 수정 과정으로 옮기고, 행동과 실패 전이를 재현 가능하게 분석한다.

### B. 잘못된 일치에서 벗어나는 원출처 확인

- 질문: 모델과 초기 문서가 같은 오답에 동의할 때, 원자료를 확인하는 행동이 오류를 깨는가?
- Task: A와 같은 입력·출력에 재인용·단일 원자료·독립 관측 태그를 추가한다.
- 비교: A의 방법들과 단순 중복 제거, 무조건 반대 검색을 작은 진단 집합에서 비교한다.
- 핵심 결과: 잘못된 일치 집단의 회복, 원출처 실제 열람, 정당한 단일 출처에서의 과잉 보류.
- 부담: 높음. 문서 내용의 참거짓 외에 출처 관계 정답을 사람이 작성해야 한다.
- 기여의 형태: 정적인 중복 필터에서 남는 불확실성이 실제 추가 행동으로 해소되는지 분석한다.

### C. 오래된 지식과 바뀐 사실의 구분

- 질문: 현재 유효한 정보로 갱신하되, 과거 시점의 참인 자료를 거짓으로 오판하지 않는가?
- Task: 같은 주장에 대상 시점과 근거 공개 시점을 명시하여 검증한다.
- 핵심 결과: 시간 범위 정합성, 오래된 답의 갱신, 불필요한 수정.
- 부담: 중. 버전·날짜·과거 상태 정답이 있는 자료 확보가 중요하다.
- 기여의 형태: 실세계 조건·버전 차이가 겉보기 충돌을 만드는 과정을 분석한다.

**추천:** A를 주 연구로 삼고, B의 대표 사례를 진단에 넣고, C는 모든 자료의 시점 메타데이터와 오류 분석에 반영한다. 세 가지를 각각 독립 시스템으로 만들기보다 하나의 검증 Agent에서 확인한다.

## 5. 추천 Task의 입출력과 행동

### 입력

- 선정 주장 하나, 대상 시점·범위, 자료의 공개 허용 시점.
- 초기 문서와 구절. 출처 URL·발표/갱신 시각 등 실제 공개 메타데이터.
- 모든 방법이 접근할 수 있는 같은 검색·열람 도구와 예산.

### 출력

- Supported / Refuted / NEI 판정, 그리고 별도의 종료 상태.
- 판정에 필요한 핵심 사실값·단위·시점.
- 실제 확인한 문서 ID와 인용 구절.
- 초기 판정을 유지하거나 수정한 이유를 1~3문장으로 설명.
- 도구 호출·관측·시간·토큰 기록.

### 작은 개선 방법: 검증할 빈칸을 기록하고 다음 행동으로 연결

다음 네 항목만 가진 근거 기록표로 시작한다.

| 기록 | 예 | 다음 행동으로의 연결 |
|---|---|---|
| 미확인 요소 | 설립인가 이전인가? 어느 제품·기간인가? | 해당 조건을 포함한 중립 질의 |
| 지지·반박 근거 | D1은 2022년, D4는 2020년을 말함 | 양쪽 구절의 대상·시점 확인 |
| 관찰한 출처 관계 | D1~D3가 같은 발표문을 인용 | 그 발표문을 실제로 열람 |
| 남은 조사 목적 | 근거가 발표 사실만 입증하는가? | 주장에 필요한 관측·결과 자료 검색 |

Agent가 선택할 도구는 search와 open으로 충분하다. 원출처 추적은 open 또는 search로 구현할 수 있다. 단순 계산이 필요한 사례에서만 공통 계산 도구를 제공한다. 관계를 확인하지 못한 문서는 ‘관계 미확인’으로 유지한다.

검색 질의는 현재 답을 지지하는 문장으로만 만들지 않는다. 먼저 어떤 관측이 후보 설명들을 구별하는지 적고 그 관측을 찾는다. 예컨대 ‘A기관 2022 설립 증거’보다 ‘A기관 공식 연혁 설립 이전 연도’가 구별에 적합할 수 있다. 항상 반대말을 검색하는 고정 규칙과 비교할 수 있는 지점이다.

최종 수정 시에는 새 근거가 같은 주체·기간·범위를 다루는지, 원자료가 무엇인지, 실제 어느 구절이 판단을 바꾸는지를 연결한다. 판정을 유지할 때도 동일한 근거 기준을 적용한다.

### 원본과 통제 변형을 분리

원본 주장 c는 유지하고 초기 자료 E₀를 두 버전으로 구성할 수 있다.

1. **기준 자료:** 올바른 판정에 도움이 되는, 시점과 범위가 맞는 근거.
2. **오도 자료:** 현실적인 수치·주체·시점 오류 또는 잘못된 재인용을 가진 자료.

두 버전은 문서 수·길이·형식·노출 순서를 최대한 맞추고 바뀐 요소를 기록한다. 실제 오류 기사로 비교하면 현실성이 높고, 통제된 변형으로 비교하면 무엇을 바꿨는지 명확해진다. 이 두 종류는 결과에서 나누어 보고한다. 변형 자료는 별도 ID와 원본 연결을 가진 로컬 평가 자료로 관리한다.

**50개 기본 주장에 자료 조건이 두 개라면 100개 입력 조건이지, 독립된 평가 사실 100개가 아니다.** 같은 사건·파생 조건은 같은 평가 그룹에 둔다.

원래의 ‘참/거짓 주장 × 참/거짓 근거’ 2×2도 유지할 수 있다. 다만 근거가 사실인지와 그 문장이 주장을 지지하는지는 별도다. 거짓 근거끼리도 내용은 다를 수 있으므로, 각 구절에 사실성·지지 방향·시간 범위를 따로 기록한다. NEI는 사실 참거짓이 확정된 네 칸 밖에서 별도로 다룬다.

### 내부 지식 상태는 사전 응답으로 관찰

한 모델 버전을 고정하고 공개 학습 정보·공개일을 기록한다. 사실값을 묻는 중립 질문을 세 표현으로 작성해 새 문맥에서 질의한다. 예/아니오만 맞히는 것보다 핵심 사실값을 맞히는지 확인한다.

- 세 표현 모두 정답: 안정적 초기 정답 집단.
- 같은 오답을 일관되게 냄: 안정적 초기 오답 집단.
- 응답 불일치·보류: 불안정/보류 집단.

이 태그는 채점과 분석에만 사용한다. 모델이 이미 맞히는 사례만 남기지 않고 전체 성능과 집단별 결과를 함께 보고한다. 기존 50개에서 안정적 정답 사례가 너무 적다면, 같은 분야의 유명하고 변하지 않는 사실 5~10개를 별도 진단 집합으로 추가한다. 실제 개수는 probe 후 보고한다.

모델 공개 이후 처음 결정·공개된 사건은 새로운 정보 조건을 만드는 강한 근거다. 선언된 학습 cutoff는 보조 메타데이터로 사용한다. 자원별 유효 cutoff가 다를 수 있다는 [Dated Data](https://arxiv.org/html/2403.12958v2)의 결과를 반영한다.

## 7. 비교 실험을 작게 시작하는 방법

| 역할 | 방법 | 공통 조건 |
|---|---|---|
| 출발점 진단 | 자료 없는 응답 p, 초기 자료만 읽은 a₀ | 별도 probe, 동일 E₀ |
| B1 | 고정 검증 절차: 중립 검색·원출처/시점 확인·판정 | 같은 모델·도구·검색 공간·최대 예산 |
| B2 | 일반 ReAct: 검색·열람·종료를 자유롭게 선택 | B1과 동일한 자원 |
| P | 근거 기록표를 이용하는 ReAct | 도구 능력은 그대로, 판단에 쓰는 기록과 지침 변경 |

판정 수정 실험에서는 동일한 a₀에서 세 방법을 분기시킨다. 공통 초기 호출도 각 방법의 총비용에 포함해 보고한다. 물리적으로 재사용한 호출 수는 별도로 기록한다.

주 실험은 고정된 자료 모음과 검색 색인을 사용한다. 자료는 처음부터 모두 주지 않고 Agent가 쿼리와 열람 대상을 선택해 확보한다. 고정 corpus에서도 순서와 행동을 스스로 고르면 능동 검증을 평가할 수 있다. 실제 웹 실험은 소수 사례의 별도 점검으로 둔다.

### 순서

1. **개발용 6개:** 정확한 근거, 오도 근거, 최신 정보, 잘못된 일치, 정당한 단일 출처, 시간·대상 혼동을 포함해 실행 흐름을 점검한다.
2. **본 평가 50개:** 같은 초기 자료를 모든 방법에 주고 GSR·판단 변화·비용을 비교한다.
3. **통제 진단:** 같은 주장의 기준/오도 자료 쌍으로 원인을 확인한다. 먼저 10~12개로 시작하고 결과와 예산에 따라 50개까지 확대할 수 있다.
4. **오류 분석 후 개선:** 예컨대 원문을 찾고도 과거 날짜를 현재에 적용하는 실패가 나오면, 대상 기간 확인을 추가하고 고정된 평가 조건에서 전후를 비교한다.

### 부담을 가늠하는 산식

본 평가 50개 × 3방법 = 150개 방법별 실행이다. 한 실행에 공통 초기 판정 1회와 이후 최대 4회 추론을 허용한다면 비용 집계상 상한은 750회다. 세 표현의 closed-book probe를 모두 쓰면 150회가 더해진다. 실제 물리 호출은 공유 초기 판정 재사용과 조기 종료로 줄어든다. 검색·열람 횟수와 비용은 따로 센다.

50개 전체를 두 자료 조건으로 늘리면 방법별 실행 300개, 같은 상한의 추론 1,500회와 probe 150회다. 그래서 처음부터 두 모델·여러 반복·모든 보조 조건을 곱하지 않고 한 모델과 작은 파일럿부터 시작한다. 이는 예산 산식 예시이며 실행 승인은 별도다.

## 8. 추천 metric과 정확한 분모

G는 검수된 정답, a₀는 초기 자료를 읽은 공통 판정, a_f는 최종 판정이다. C(a)는 라벨과 판정에 필수적인 사실값·대상 범위가 맞는지를 나타낸다. 인용의 충분성은 별도로 평가한다.

| 지표 | 정의 | 답할 질문 |
|---|---|---|
| **근거 동반 성공률 GSR** | 올바른 판정 AND 충분한 실제 인용 AND 올바른 시간 범위인 실행 / 전체 평가 실행 | 맞게 설명하고 검증했는가? |
| **초기 오답 교정률** | C(a₀)=0이고 C(a_f)=1인 실행 / 유효한 초기 오답 실행 | 틀린 판단을 얼마나 고쳤는가? |
| **초기 정답 보존율** | C(a₀)=1이고 C(a_f)=1인 실행 / 초기 정답 실행 | 맞던 판단을 유지했는가? |
| **유해한 수정률** | 초기 정답에서 잘못된 최종 사실 판정을 낸 실행 / 초기 정답 실행 | 새 조사로 오히려 틀렸는가? |
| **Macro-F1·라벨별 P/R** | 사전에 고정한 라벨·실패 처리 규칙으로 계산 | 다수 라벨에 치우치지 않는가? |
| **비용·안정성** | 추론/검색/열람 수, 토큰, 시간, 실패율 | 이 개선을 얻는 데 무엇을 썼는가? |

초기 정답 집단의 결과는 정답 유지 / 잘못된 사실 판정 / 보류 / 실행 실패로 나누어 합이 1이 되게 한다. 보류와 실행 실패를 유해한 사실 주장과 같은 것으로 부르지 않는다. 초기 보류에서 정답으로 간 경우는 별도의 정보 획득 성공으로 보고한다. 분모가 0이면 0% 대신 해당 없음과 사례 수를 표기한다.

추가로 p가 안정적 정답이었던 사례에서 p → a₀ → a_f를 보면 ‘초기 자료에 오염되었지만 재검색으로 복구’한 경우와 ‘처음부터 끝까지 보존’한 경우를 구분할 수 있다. p가 틀리고 E₀도 같은 오답을 지지하는 사례는 잘못된 일치 집단으로 따로 집계한다.

### 행동을 읽기 위한 진단 지표 두 개

- **충분한 근거 실제 열람률:** 허용 예산 안에 사람이 인정한 충분 근거 집합을 실제로 열람한 실행 / 해당 집합이 검색 공간에 존재하는 실행. 검색 결과에 URL만 나온 경우와 본문 확인을 구분한다.
- **근거 확보 후 해석 성공률:** 충분한 근거를 열람한 실행 중 최종 판정·범위가 맞은 비율.

이를 통해 ‘찾지 못함’, ‘찾았지만 읽지 않음’, ‘읽었지만 잘못 해석함’, ‘판정은 맞지만 인용이 부족함’을 분리한다. 사람이 정한 단 하나의 검색어·도구 순서와 일치하는지를 정답 기준으로 삼지 않는다.

GSR과 비용을 주 결과로, 보존·교정을 공동 진단으로 삼는다. 임의의 가중치로 모두 합친 새 점수 하나를 만들기보다, 각 사례에서 어느 방향의 변화가 있었는지 함께 제시한다. 방법 간 차이는 동일 주장 단위로 짝지어 비교하고, 파생 자료가 있으면 주장/사건 그룹 단위로 불확실성을 계산한다.

## 9. 독창성과 난이도를 발표에서 설명하는 문장

**문제의식:** 외부 자료는 기존 오류를 고치는 수단이면서, 맞던 판단을 오염시키는 원인이기도 하다. Agent의 추가 검색도 같은 양면성을 가진다.

**우리의 구현:** 같은 모델·도구·예산 안에서, 확인할 사실 요소와 근거의 출처·시점을 기록하고 그 빈칸을 다음 검색 목표로 연결한다.

**우리의 실험:** 실제 기사 기반 사례와 통제된 자료 변형에서, 초기 상태부터 최종 판정까지의 보존·교정·오염·보류를 구분하고 어떤 행동이 결과와 연결됐는지 분석한다.

**학부 프로젝트로서의 기여:** 자체 검수 데이터, 재현 가능한 비교, 작은 정책 개선과 전후 오류 분석을 함께 제공한다. 난이도는 도구 개수보다 불완전한 근거를 해석하고 적절한 다음 행동을 선택하는 과정에 있다.

발표에서는 가까운 연구를 먼저 인정하고 비교한다. ClashEval은 출발 상태와 수정의 양방향을, CRITIC/FIRE는 추가 행동을, Evidence Laundering은 잘못된 일치를, BeliefRAG는 상태 기반 검색 제어를 다룬다. 그 교집합에서 우리가 평가할 구체적 조건과 구현한 차이를 보여준다.

## 10. 세 사람이 읽고 논의할 순서

1. **모두 공통:** ClashEval의 §3.1과 Table 3. 무엇을 ‘교정’과 ‘오염’으로 세는지 확인한다.
2. **판단·지식 축:** Real Documents → Astute RAG → Micro-Act. 답 변경과 올바른 변경의 차이, 충돌 해석을 읽는다.
3. **Agent 축:** CRITIC → FIRE → BeliefRAG/SEAC. 추가 행동과 종료를 어떻게 정의하고 비용을 맞추는지 읽는다.
4. **근거 품질 축:** Evidence Laundering → FVA-RAG. 같은 내용의 반복과 반대 근거가 각각 무엇을 증명하는지 읽는다.

공통으로 남길 메모는 ‘입력/출력’, ‘실제 행동’, ‘정답 접근 여부’, ‘핵심 비교군’, ‘결과의 분모’, ‘우리에게 가져올 한 가지’다. 이번 추천을 팀에서 확정할 때에는 A를 중심으로 삼을지, B에 더 큰 비중을 둘지와 사용할 초기 자료 조건을 결정하면 된다.

## 11. 범위·출처·유의사항

- **확정된 관점과 제안의 구분:** 사용자가 합의한 것은 내부 지식·초기 외부 근거·능동 획득 근거의 상호작용과 교정 가능성이라는 관점이다. 세부 방법·모델·수량·예산은 이 문서의 추천 설계이며 팀의 최종 결정이나 실험 결과가 아니다.
- **현재 작업:** 문헌 조사와 설계 문서를 작성했다. 실험용 모델 호출, 데이터 변형, 정답 확정, GitHub push/merge는 수행하지 않았다.
- **신규성:** 내부/외부 충돌, 자기교정, 반대 근거 검색, 상태 기반 재검색, 정답 보존은 각각 선행연구가 있다. 이번 조사로 전 세계 연구 공백을 증명하지 않는다. 제안의 차이는 특정 평가 조건과 구현·오류 분석으로 검증한다.
- **모델 지식:** 세 번 정답은 세 번의 관찰이지 학습 데이터 포함 증명이나 정답 확률 100%가 아니다. θ는 실험 중 고정하며 답변 갱신을 가중치 학습으로 해석하지 않는다. 사전학습뿐 아니라 후속 학습도 현재 파라미터에 영향을 줄 수 있다.
- **세 경로:** 초기 자료와 추가 수집 자료는 모델에게 모두 외부 문맥이다. 추가 fetch라는 이유만으로 최신·독립·정확하다고 보지 않는다. 새 자료가 틀린 경우를 진단에 넣는다면 초기 자료 조작과 별도 조건으로 구분한다.
- **금표준:** 50개 자료는 지지 37·반박 11·NEI 후보 1·보류 1, 47개 그룹인 작성 단계 자료다. 독립 검수·불일치 조정·근거 확보를 거쳐 고정한다. 현재 색인에 있는 사실을 이번 작업에서 모두 재검증한 것은 아니다.
- **데이터 변경:** 원본 카드와 판정을 보존한다. 새로운 주장은 파생 ID, 인공 자료는 변형 ID와 생성 이유를 가진다. ‘주장이 발표되었다’를 ‘주장이 사실이다’로 조용히 바꾸지 않는다. 모델이 틀릴 사례만 사후 선택해 전체 성능처럼 보고하지 않는다.
- **보류·NEI:** NEI 정답은 정해진 자료·시점·조사 범위에서 판정 근거가 부족하다는 별도 라벨이다. 검색 실패나 모델 자신감 부족은 그 자체로 NEI 금표준이 아니다. NEI가 한 건인 상태에서 그 라벨의 일반 성능을 주장하지 않는다.
- **선택·평가 누출:** 개발 사례와 최종 평가 사례를 분리한다. gold 라벨·근거 정답 목록·자료의 참거짓 태그·probe 정오를 정책 입력에 주지 않는다. ‘틀렸을 때만 재검색’을 정답표로 구현하면 oracle 실험이다.
- **공정성:** 검색 공간에 정답 근거가 있는 진단은 회복 가능성 평가이며 일반 웹 성공률과 구분한다. 출처 정답을 도구가 반환하지 않는다. 문서 수·길이·검색 순위 차이도 결과에 영향을 줄 수 있으므로 기록·통제한다.
- **불확실성:** 같은 자료를 반복·변형했다고 독립 표본이 늘지 않는다. 50개에서는 한 사례가 2%p이며 소집단 비율의 분모를 함께 제시한다. 한 모델의 결과를 모든 LLM에 일반화하지 않는다.
- **자원·수업 조건:** 강의자료의 local/free 모델 활용 조건을 기준으로 평가 모델을 정한다. 학습·RL·여러 Agent·vector DB 교체는 핵심 가설에 꼭 필요할 때 별도 확장한다. 현재 산식은 실행 예산 승인이나 완료 시간 추정이 아니다.
- **문헌 확인:** 핵심 원문은 방법·결과 관련 절을 확인했으며 저자 코드를 실행·재현하지 않았다. 최신 preprint와 학회 논문을 구분한다. 상세 확인 범위와 논문별 링크는 문헌검토, 검색 횟수와 URL은 search_log.json에 기록했다.
