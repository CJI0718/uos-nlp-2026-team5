# 001 · 팩트체크 Agent로 연구의 큰 방향 합의

- 기록일: 2026-10-23
- 상태: **큰 방향 합의 / 세부 실험 설계 제안 단계**
- 근거: 사용자가 팀원과 논의한 결과로 기사·뉴스·소식·주장을 검증하는 Agent를 제안했고, 이 구상을 정리·조사해 저장소에 반영하도록 요청했다.

## 합의된 큰 방향

자연어로 주어진 주장이나 기사에서 검증할 내용을 식별하고, RSS·문서 검색·공식 자료 API 등의 도구로 증거를 수집·대조해 근거와 함께 판정을 설명하는 에이전트를 탐구한다. Retrieval, ReAct 방식의 도구 활용, 근거 기반 generation을 연결한다.

## 아직 합의하지 않은 것

대상 분야와 언어 범위, 구체적 연구 질문, 3/4-class label 체계, 데이터셋·50개 구성, RSS/API 공급자, 모델·GPU·예산, multi-agent 여부, 학습/RL 여부, 제출용 최종 실험은 미정이다. 문헌집의 baseline·metric·도구 설계는 모두 검토할 제안이다.

“Agent만 해결할 수 있다”, “사람보다 우수하다”, “한국어 팩트체크가 최초다”는 확정된 결론이 아니다. 같은 모델·도구·예산의 강한 고정 workflow와 비교해 적응적 결정이 필요한 조건을 검증한다.

## 이전 탐색과의 관계

기존 49개 후보는 선택 과정의 기록으로 보존한다. R2(주장 검증), R5(시점), R6(추가 검색·보류), H3(예산·종료) 등이 주제 구체화에 이어진다. 나머지 후보를 실패하거나 가치 없는 주제로 판정한 것은 아니다.

## 예상 위험과 재검토 조건

- 검수 가능한 gold와 사용 가능한 자료가 없으면 먼저 domain·task 범위를 줄인다.
- 기존 fact-check 답을 검색해 복사하는 실험이 되지 않도록 label/판정문 누출을 구분한다.
- 공식 API만으로 모든 주장을 해결할 수 없으면 텍스트 근거 track과 수치 track을 분리한다.
- 비용·시간 문제가 있으면 고정 store에서 재현 가능한 최소 비교부터 한다.
- 학습·가중치 다운로드·모델 실험은 별도 실행 요청과 예산 승인 후 수행한다.
