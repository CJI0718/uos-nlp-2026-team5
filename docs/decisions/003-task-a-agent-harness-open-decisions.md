# 003 · Task A 에이전트 실험 — 팀이 정할 항목 (초안)

- 상태: **제안**. 아래 항목은 하나도 합의되지 않았습니다. 선택지와 비용만 정리했습니다.
- 작성: 2026-11-19, `feat/agent-skill-mcp` 브랜치(실험용) 기준.
- 관련 코드·문서: [experiments/README.md](../../experiments/README.md), [data/README.md](../../data/README.md), [missions/README.md](../../missions/README.md)

## 무엇을 하는 실험인가

에이전트는 주장 하나를 받습니다. 예를 들어 FC001 "S24 울트라 1TB는 2,127,400원이며 S23 울트라 1TB보다 165,000원, 약 8.4% 비싸다"입니다.
에이전트는 MCP 도구로 원문 코퍼스를 검색합니다. 이 사례에서는 삼성전자 뉴스룸 보도자료 두 건을 읽고, `calculate_comparison`으로 차액과 인상률을 계산한 뒤
`finish_verification`으로 판정(`supported`)과 근거를 제출합니다. 후속 미션(일정 `.ics`, 정리 문서 `.md`)은 서버가 최종 판정과 실제로 읽은 근거를 확인한 뒤에만 실행합니다.
채점기는 판정을 `gold.jsonl`과 비교합니다.

이 브랜치에서 지금 되는 것:
- C0(자료 없음)와 C1(원문 코퍼스 54개 문서)로 서버가 뜨고, 격리 작업공간과 실행 명령이 만들어집니다.
- 채점기는 정확도, Macro-F1, 커버리지, 상수 답 기준선, 미션 안전성을 냅니다.

실제 모델 실행은 아래 1번이 정해지기 전에는 하지 않습니다.

## 정할 항목

### 1. 실행 승인과 호출 예산

- 질문: 어떤 에이전트·모델로, 몇 번까지 실행해도 되는가?
- 규모: 주장 50건마다 새 세션 하나입니다. 한 세션의 도구 호출 상한은 12회입니다(서버 예산).

  | 묶음 | 세션 수 |
  | :--- | ---: |
  | C0 하나 (파일럿) | 50 |
  | C0·C1 × Skill 유무 | 200 |
  | C0·C1·C2 × Skill 유무 | 300 |
  | 위 묶음을 반복 3회 | ×3 |

- 고려한 대안: (a) 한 모델로 C0 50건 파일럿 후 확대, (b) 처음부터 C0·C1 비교, (c) 에이전트 여러 개 비교.
- 예상 비용·위험: 구독형 에이전트는 사용량 한도, API 키 방식은 토큰 비용이 듭니다. C2는 외부 검색 API(Tavily 무료 월 1,000회 등)를 함께 씁니다.

### 2. 실행 구조 — 외부 에이전트에 연결 vs 자체 루프

- 질문: 이 브랜치처럼 Claude Code 같은 기존 에이전트에 MCP 서버와 Skill을 연결할 것인가, 자체 에이전트 루프를 다시 둘 것인가?
- 외부 에이전트 연결: 구현이 작고, 도구·게이트·로그·채점이 에이전트와 분리됩니다. 대신 에이전트 내부(프롬프트, 재시도)는 통제하지 못하고, 버전이 바뀌면 결과가 달라질 수 있습니다. 그래서 `--model-id`에 에이전트와 모델 버전을 함께 기록합니다.
- 자체 루프: 모든 단계를 통제·기록할 수 있지만 구현과 유지 비용이 큽니다. 이 브랜치에서는 커밋 `000aded`에서 제거했습니다.
- 다시 검토할 조건: 과제 평가에서 "에이전트를 직접 구현"하는 것이 요구되는 경우.

### 3. 개발용·평가용 사례 나누기

- 질문: Skill을 다듬을 때 볼 사례와 점수를 낼 사례를 어떻게 나누는가?
- 현재: Skill은 같은 50건을 보며 만들어졌습니다. 정답 예시는 지웠지만 효과가 낙관적으로 나올 수 있습니다.
- 고려한 대안: (a) 50건을 `family_id` 단위로 개발 10 / 평가 40으로 나눔, (b) 개발용 사례를 새로 작성하고 50건은 평가에만 씀, (c) 나누지 않고 한계로 보고.
- 예상 비용·위험: (a)는 평가 표본이 더 작아집니다(반박 정답 11건 중 일부가 빠짐). (b)는 사례 작성과 검수 시간이 듭니다.

### 4. 코퍼스의 방해 문서

- 질문: 원문 코퍼스에 정답 근거 외에 어떤 문서를 넣는가?
- 현재: 정답 근거 원문 54개만 있습니다. 그래도 주장 문장으로 BM25 검색을 하면 맞는 문서가 1위인 경우가 46건 중 15~17건입니다.
- 고려한 대안: (a) 넣지 않음, (b) 같은 사이트·같은 주제의 다른 페이지, (c) `evidence_cutoff` 이전 검색 결과 상위 N개, (d) 같은 보도자료의 전재 기사(`provenance_group`으로 묶어 출처 독립성 평가에 사용).
- 구현: `scripts/build_corpus.py --extra-urls`에 URL 목록만 주면 됩니다. 목록을 고르는 일이 사람 몫입니다.

### 5. 코퍼스 공유와 재현

- 질문: 원문 코퍼스를 누가 한 번 만들어 공유할 것인가, 각자 만들 것인가?
- 이유: 페이지는 바뀌고, 원문은 저작권 때문에 Git에 올리지 않습니다. 각자 만들면 실행마다 코퍼스가 달라질 수 있습니다.
- 고려한 대안: (a) 한 사람이 만들고 Git 밖(팀 드라이브 등)에서 공유하며, 문서별 `content_hash` 목록만 저장소에 기록, (b) 각자 만들고 보고서(`corpus_c1.report.json`)를 실험 기록에 첨부.

### 6. gold 검수와 판정 보류 사례

- 질문: 초안 상태인 판정 49건을 누가 검수하고, 판정 보류인 FC038을 어떻게 처리하는가?
- 현재 분포: 지지 37, 반박 11, 근거 부족 1, 보류 1. 항상 "지지"라고만 답해도 정확도가 75.5%입니다.
- 고려한 대안: (a) 두 명이 독립 검수하고 불일치만 논의, (b) 한 명 검수 후 다른 한 명 표본 확인, (c) 반박·근거 부족 사례를 추가해 분포를 맞춤.

### 7. 왜곡 유형 채점

- 질문: 판정 외에 `distortion_type`·`problematic_span`·`correction`도 채점하는가?
- 현재: gold에 왜곡 유형 필드가 없어서 채점하지 않습니다. 에이전트는 Skill에 따라 제출하고 로그에 남습니다.
- 고려한 대안: (a) 반박 11건에 사람이 `distortion_type`을 붙이고 정확 일치로 채점, (b) 범위 밖으로 선언.
- 예상 비용·위험: (a)는 표본이 11건이라 유형별 비교는 어렵습니다.

### 8. 근거 조건 변형 (missing·conflict·misleading)

- 질문: 근거가 빠지거나, 충돌하거나, 오도하는 조건을 만들 것인가? 만든다면 어떻게 만드는가?
- 현재: 서버가 이 조건을 거부합니다. 4번(방해 문서)과 5번(공유)이 정해져야 변형 코퍼스를 만들 수 있습니다.
- 고려한 대안: (a) missing은 대응표(`corpus_c1.gold_map.jsonl`)로 정답 문서를 빼서 자동 생성, conflict·misleading은 사람이 고른 실제 문서로 구성, (b) 셋 다 사람이 구성, (c) sufficient만 실험.

### 9. C2 웹 검색의 시점 제한

- 질문: C2에서 `evidence_cutoff` 이후 문서를 코드로 막을 것인가?
- 현재: Skill이 지시만 합니다. 검색 결과에 발행일이 없는 경우가 많아 완전히 막기는 어렵습니다.
- 고려한 대안: (a) 발행일이 cutoff 이후인 결과는 서버가 차단하고, 날짜를 모르는 결과는 표시만 함, (b) 지시만 유지하고 사후에 로그로 위반을 셈.

### 10. 비교할 에이전트

- 질문: Claude Code 외에 Codex·Cursor 등도 비교하는가?
- 현재: 격리 작업공간은 Claude Code 설정만 생성합니다.
- 고려한 대안: (a) 한 에이전트로 고정, (b) 둘 이상 비교. (b)는 각 도구 설정 형식에 맞춰 같은 격리(내장 파일·셸·웹 도구 차단, 다른 MCP 서버 차단)를 맞춰야 합니다.

## 범위와 유의사항

- 이 문서는 선택지 정리이고 결정이 아닙니다. 합의되면 항목별로 상태를 "합의"로 바꾸고, 선택과 이유, 선택하지 않은 대안을 채웁니다.
- 숫자(문서 54개, 주장 46/50건, BM25 1위 15~17/46)는 2026-11-19 수집 결과입니다. 사이트가 바뀌면 달라집니다. 측정 방법은 [data/README.md](../../data/README.md)에 있습니다.
- 실제 모델 실행 결과는 없습니다. 어떤 선택지가 성능에 유리한지는 실행 전까지 알 수 없습니다.
