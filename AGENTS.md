# Project instructions

- Read README.md and CONTRIBUTING.md before changing this repository.
- The project is in brainstorming: do not choose the research topic, models, or budgets without a team decision.
- Keep paper claims, proposed methods, and observed experimental results distinct. Cite original sources and dates.
- Use focused changes and preserve existing records. Never invent data, results, citations, or completion.
- Do not execute paid/free experimental model calls, automatically retry, or switch models without explicit run authorization and a call budget.
- Never commit credentials, personal data, raw private trajectories, copyrighted source material without permission, model weights, or caches.
- Store human-checked evaluation data separately from prompts shown to the solving agent; avoid answer leakage.
- Record decisions and reproducible experimental settings. Prefer deterministic checks before adding LLM judges.
- Do not push to main, merge PRs, change repository visibility, invite people, or publish releases unless the user explicitly requests that action.
- Do not turn this coursework into a general-purpose framework unless needed for an agreed research question.

## Team research documents

- Follow `docs/documentation-guidelines.md` when creating or updating team-facing research Markdown and HTML.
- Start with a concrete task and an example for a new teammate. Connect inputs, agent decisions, outputs, course requirements, evaluation cases, metrics, and implementation effort.
- Use Markdown as the editing source and generate the HTML from it. Offer a small reading entry point, task-based paper filters, and a collapsible full library.
- Introduce papers through their research question, architecture, reported results, team application, and sections to read; verify original sources and distinguish reported facts from proposed work.
- Consolidate scope notes, unperformed work, limitations, and caveats into one dedicated chapter instead of repeating them throughout the guide.
- Check relevant teammate branches and exact commits as well as main, preserve their contributions, and cite the source of incorporated proposals.
